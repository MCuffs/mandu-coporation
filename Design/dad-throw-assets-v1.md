# 가로형 투척 게임 — 기본 에셋 v1

2026-11-17. [전략 기획](dad-throw-strategy-v1.md)의 전투 화면과 시작 화면을 위한 원화 팩. 내장 imagegen으로 기존 아빠 원화를 인물·그림체 참조하여 새로 생성한다. 코드·본편·기존 V20를 교체하지 않는다.

## 방향과 납품

병맛 한국 만화풍, 굵은 먹선, 평면 색, 최소한의 명암. 치킨집 시안 D의 도트풍과 구분한다. 가로1280×720 논리 화면, 고정 옆면 시점, 오른쪽으로 투척한다. 바닥선은 y570(높이 약79.17%). 아빠는 고정되고 물건만 날아간다.

## 재사용과 코드로 유지할 것

- 상대: 기존 DadV5/DadV7 gum 걷기·피격 프레임 재사용. 한 종류가 충분한지 플레이로 먼저 확인한다.
- 글자·체력·웨이브·정지·강화/다음/재도전 버튼: 현재 코드에서 그린다. 글자를 이미지에 굽지 않는다.
- 투사체 꼬리/조준 점선/피격 짧은 효과: 코드 렌더링 유지. 폭발 장식·타격 문구를 원화에 추가하지 않는다.
- 완료/실패/정지는 기존 전투 위 오버레이로 구성하므로 각각 별도 전체 배경을 생성하지 않는다.
- 골프채·자동차·낚싯대 및 다수의 상대 신종은 이번 팩에 포함하지 않는다.

## 임포트와 연결 규칙

PNG RGBA 유지, 투명 이미지는 alpha transparency, Bilinear, Clamp, mipmap 없음, NPOT 강제 변환 없음, 무압축, 최대2048. 폴더와 각 파일의 .meta를 함께 생성한다. 현재 엔진2021 소스 및 추후 Unity6 Android 빌드 사본에서 같은 설정인지 확인한다. 픽셀 엄격 모드/Point 필터는 이 만화풍에 적용하지 않는다.

포즈의 원본 캔버스 크기가 달라도 동일한 표시 신장과 발 중심 앵커를 사용한다. manifest의 pivot은 alpha 바닥 근처의 발 영역에서 구한 **연결 시작점**이다. 실제 애니메이션에서 발이 움직이지 않는지 확인 후 채택한다. 팔이 뻗은 전체 bounding box 중심을 몸 중심으로 쓰지 않는다. 공은 원형 중심, 신발은 alpha bounding box 중심을 회전 기준으로 쓴다.

배경을 그냥 늘려 기존 코드 위에 덧씌우지 않는다. 수평 바닥을 논리 y570에 맞추고, 집 그림과 모델 실패 경계 x155를 대조해야 한다. 제목 원화도 live text/버튼 위치와 겹치는지 가로 화면에서 확인한다.

## 상태와 검증 한계

이 문서는 생성·파일 검사 후 실제 납품 결과를 아래에 추가한다. Unity 창·플레이어·Android를 실행하지 않는다. 리소스 폴더에 파일이 존재하는 것과 게임 코드가 사용한다는 것은 다르다. **이번 단계는 에셋 납품이며 런타임 적용·새 APK는 별도다.** 개별 포즈가 생성됐다는 이유만으로 자연스러운 애니메이션을 검증했다고 주장하지 않는다.

## 납품 결과

7종 PNG를 원본/리소스 경로에 복사했고 모든 이미지의 alpha 경계·UV·피벗·크기를 manifest에 기록했다. 임포트 설정·원본/복사본 해시 일치·GUID 중복·UV 범위 검사는7종 모두 통과했다([검사 기록](dad-throw-assets-v1-checks.txt)). 모든 출력은 직접 열어 확인했다.

- [에셋 비교 페이지](dad-throw-assets-v1/index.html), [한 장 미리보기](dad-throw-assets-v1/overview.png). 브라우저 무창 렌더이며 Unity 캡처가 아니다.
- 생성된 windup의 손에 작은 흰 공이 남아 targeted edit로 제거한 버전을 채택했다. 최초 생성 프롬프트와 수정 프롬프트를 함께 보존했다.
- 배경/타이틀1672×941, 아빠 포즈와 공1254×1254, 신발1774×887. 모두 최대2048 이내이며 원본을 리사이즈하지 않았다.
- 배경의 실제 수평 바닥은 약83.1% 위치로 생성되어 요청한79.17%와 다르다. manifest에 `groundNormalizedY: 0.831`을 기록했다. 논리720 높이로 그릴 경우 y를 약−28.3 이동하면 바닥570에 맞는다. 집 앞 경계도 약16.8%로 생성돼 모델의x155와 그대로 일치하지 않는다. 배경 크롭/오프셋과 모델 경계를 같이 조정해 확인해야 한다. 비율이 안 맞는 원화를 강제로 늘려 맞추지 않는다.
- 포즈는 발 중심 앵커로 연결 준비했지만 다리 간격과 상체 기울기가 서로 다르다.3프레임을 고속 순환하는 완성 애니메이션이 아니라 준비→당기기→방출의 키포즈다. 타이밍·발 미끄러짐·실제 발사 손 앵커는 런타임 연결 단계에서 확인한다.
- 코드·시작 씬·본편·V20를 수정하지 않았고, Unity 창 실행·새 APK·커밋·푸시는 하지 않았다.
- 2026-11-17 후속: 런타임 연결은 [시제품 구현 기록의 "ThrowV1 에셋 런타임 연결"](dad-landscape-throw-prototype-v1.md)에 따로 적었다. 그때 manifest에 `handPixels`와 `sandTopNormalizedY`가 추가됐고 기존 값은 바뀌지 않았다.
