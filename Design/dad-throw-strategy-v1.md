# 아빠 전쟁 — 가로형 투척 디펜스 전략 기획 v1

작성일: 2026-11-17  
상태: **합의된 방향을 바탕으로 한 게임별 전략 초안**. 별도 시제품 구현과 본편 교체·정식 출시 승인은 구분한다.

## 1. 한 문장 기획

**몰려오는 상대를 한 줄로 모은 뒤, 아빠가 던진 골프공 한 발로 연속 제압하는 가로형 캐주얼 디펜스.**

플레이어가 느껴야 할 감정은 ‘물건이 강해서 이겼다’뿐 아니라 **‘내가 모으고 각도를 맞혀 한 번에 쓸었다’**다. 신발로 무리를 모으는 판단과 골프공을 쏘는 순간의 보상이 첫 번째 검증 대상이다.

기존 세로형에서 아빠의 몸을 날리고 장비·강화·별을 함께 관리하던 부담을 줄인다. 아빠는 고정하고 날아가는 물건, 적의 접근, 명확한 실패 경계만 읽게 한다. 복잡한 홈 화면 대신 전투→짧은 정산→다음 전투를 중심으로 구성한다.

## 2. 확정·가정·미확인

| 구분 | 내용 |
|---|---|
| 사용자와 합의한 방향 | 가로 화면, 아빠가 집안 물건을 던짐, 많은 상대가 접근, 골프공으로 줄지은 상대를 연속 타격, 물건을 단계적으로 구매/해금 |
| 사용자 제안 물건 | 골프공·신발로 시작하고 골프채·자동차·낚싯대로 확장 |
| 현재 시제품에 구현 | 고정 아빠, 골프공/신발, 웨이브, 집 체력, 코인, 강화 하나, 조준 중 감속, 일시정지 |
| 이 문서의 제안 | 아래 성장 순서·장비 슬롯 수·특수 물건 사용 한도·웨이브 구성·시험 관문·제작 상한 |
| 미확인 | 실제 사람이 이해하고 신발을 활용하는지, 반복 재미, 유지율·수익성, 가로 화면 터치 품질, S21 실기기 성능, 전체 웨이브 난이도 |

‘돈을 주고 구매’는 우선 **게임에서 번 코인으로 해금**하는 것으로 해석했다. 실물 결제 구매는 확정하지 않는다. 코인 수급과 물건 가격도 사람 테스트 이후 정한다.

이 전략은 한국 자영업 운영 게임 회사로 전환하는 결정이 아니다. 기존 아빠 전쟁의 단일 제품 결정과 회사 전략 검토 문서는 별개다. 기존 본편·세이브·미커밋 V20는 보존한다.

## 3. 제품 목표와 범위

**대상 가정:** Android에서 짧게 즐기는 캐주얼 이용자. 출시 국가·연령·유료 유입 예산은 아직 미결정이다. 우선 한국어로 조작을 관찰한다.

| 목표 | 설계 수단 | 관찰할 행동 |
|---|---|---|
| 화면만 보고 시작 | 왼쪽 아빠, 오른쪽 접근 적, 점선 탄도, 무기2개 | 긴 설명 없이 첫 발사와 첫 타격 |
| 모아서 맞히는 판단 | 신발 밀치기/감속→뒤따르는 무리와 합류→관통 | 상황에 맞춰 무기를 바꾸고 관통 성공을 설명 |
| 짧고 명확한 재도전 | 집 체력, 짧은 웨이브, 즉시 다시 | 실패 원인을 알고 한 번 더 시도 |
| 간단한 성장 | 웨이브 사이 강화 하나, 이후 물건 해금 | 다음 물건의 다른 쓰임을 기대 |
| 1인 제작 가능성 | 기존 캐릭터 재사용, 전장 하나, 물건별 행동 차이 | 적은 자산으로 반복 상황을 만드는지 확인 |

**초기 세션 목표안:** 첫 의미 있는 타격10초 이내, 웨이브 하나30~60초, 초기 검증 콘텐츠5~10분. 현재 실측 달성값이 아니다. 대기 시간이 길면 적 체력을 올리지 말고 첫 배치·거리·간격부터 조정한다.

## 4. 핵심 행동과 전투 루프

### 4.1 기본 흐름

`적의 간격과 거리 보기 → 신발로 밀어 모으거나 바로 쏘기 → 당겨 각도·세기 정하기 → 골프공 관통/바닥 반사 → 집 앞 위협 정리 → 웨이브 완료`

좋은 선택은 다음 두 상황이 구분될 때 생긴다.

- **적이 멀고 흩어짐:** 신발로 선두를 뒤쪽 무리와 합치고, 골프공을 아낄지 먼저 한 발을 쏠지 선택한다.
- **적이 집 앞까지 접근:** 큰 관통 기회를 포기하고 신발로 즉시 시간을 번다.

‘모으기’는 적을 다른 장소에 자동 소환하는 기술이 아니다. 이미 접근 중인 무리의 **간격과 시간차를 바꾸는 행동**이다. 모든 적이 처음부터 같은 점에 겹쳐 있으면 모으는 판단이 사라지므로 실패한 배치로 본다.

### 4.2 입력 원칙

- 한 손가락으로 뒤로 당겼다 놓으면 아빠의 손 앞에서 발사한다.
- 드래그 시작 위치가 달라도 발사 위치는 고정한다. 무기 버튼·정지 영역에서는 조준을 시작하지 않는다.
- 짧은 탭과 취소된 터치는 발사하지 않는다. 앱 이탈 시 조준을 취소하고 정지한다.
- 조준 중 감속은 편의 수단이며, 감속 정도는 시험한다. 조준만 계속해 위험을 무한히 늦출 수 있으면 유지 시간 상한/자동 해제를 검토한다. 현재 시제품은 이 상한이 없다.
- 점선은 실제 발사 궤적과 일치해야 한다. 강제 보정으로 눈에 보이는 방향과 실제 발사 방향이 달라지지 않게 검수한다.

### 4.3 실패와 회복

집 경계를 넘은 상대가 집 체력을 깎는다. 체력이0이면 결과→다시 시작으로 끝낸다. 적 한 명이 새면 즉시 긴 패배 연출로 끊지 않는다. 첫 검증에서는 체력5를 사용한다.

실패 원인은 접근 거리·남은 집 체력·마지막 장면에서 읽혀야 한다. 실패 직후 설명 문단이나 여러 상품을 띄우지 않는다. 재시작 비용·에너지·광고 강제는 넣지 않는다.

## 5. 물건별 역할과 해금 전략

| 물건 | 플레이어에게 주는 행동 차이 | 도입 단계 | 한계·검증 |
|---|---|---|---|
| 골프공 | 낮은 탄도와 바닥 반사로 한 줄 관통 | 첫 시제품 | 조준·관통의 기본. 한 투사체가 같은 상대를 반복 타격하지 않음 |
| 신발 | 근거리 무리를 밀고 늦춰 뒤따르는 상대와 모으기 | 첫 시제품 | 공격보다 간격 제어에 가치. 골프공만 난사해도 항상 더 좋다면 역할 재설계 |
| 골프채 | 회전하는 긴 판정으로 넓게 흩어진 상대 타격 | 기본 재미 통과 후 | 골프공의 완전한 상위 호환이 되지 않도록 재사용 대기/관통 방식으로 구분 |
| 낚싯대 | 한 상대를 당겨 다른 무리와 충돌시키거나 재배치 | 골프채와 비교해 하나만 먼저 | 줄·훅·복귀의 추가 제작비가 큼. 자동 추적 만능 기술이 되면 제외 |
| 자동차 | 위급한 무리를 넓게 쓸어버리는 특별 투척 | 가장 뒤의 보상 후보 | 한 웨이브 사용 횟수 제한 제안. 효과가 화면 전체를 계속 덮지 않게 함 |

**동시 선택 슬롯은 초기2개, 확장해도 기본2개+특수1개 이내를 제안한다.** 모든 물건을 상시 버튼으로 늘어놓지 않는다. 해금은 선택지를 늘리는 보상이고, 장비6부위·등급·뽑기를 되살리는 구조로 만들지 않는다.

첫 상용 후보 범위는 골프공·신발과 추가 물건1종까지만 검토한다. 사용자 제안 목록 전체를 첫 출시 필수 납품으로 확정하지 않는다. 자동차·낚싯대는 비용 대비 행동 차이를 확인한 뒤 순서를 정한다.

## 6. 물량과 난이도 전략

**많은 적이 오는 것과 무엇을 해야 할지 모르는 것은 다르다.** 적 수는 관통의 보상을 키우는 수단이다. 화면 정보량·공격 속도·체력을 동시에 올리지 않는다.

### 6.1 초기 웨이브 구성안

| 구간 | 배치와 압박 | 익혀야 하는 행동 |
|---|---|---|
| 첫 발사 | 가까운 상대1명, 나머지는 뒤에서 접근 | 당기고 놓기, 맞으면 쓰러짐 |
| 첫 무리 | 간격이 좁은3~5명 | 낮게 쏴 여러 명 관통 |
| 모으기 | 선두와 후속 무리 사이에 간격 | 신발로 밀어 합친 뒤 골프공 |
| 위기 | 작은 빠른 무리와 큰 느린 무리의 시차 | 눈앞 방어와 큰 관통 기회 사이 선택 |
| 숙련 | 이미 배운 패턴의 순서·간격 변화 | 낭비 없는 무기 전환과 조준 |

위 표는 **다음 배치 튜닝안**이며 현재 시제품에 이 순서가 모두 구현됐다는 뜻은 아니다. 현재는 인원·간격·속도가 함께 증가하는 임시 수치다. 다음 튜닝에서는 한 요소씩 바꿔 원인을 분리한다.

### 6.2 조정 순서

1. **간격·무리 크기:** 모으고 관통할 기회를 만든다.
2. **등장 시차:** 다음 발사를 준비할 여유와 위기를 만든다.
3. **속도:** 이미 이해한 패턴의 판단 시간을 줄인다.
4. **특수 상대:** 기존 물건의 다른 사용처가 필요할 때 한 종류씩 추가한다.
5. **체력:** 마지막 수단. 숫자만 커져 여러 번 쏘는 노가다가 되면 되돌린다.

난이도를 적의 이동 속도·체력만으로 밀어 올리지 않는다. 조준 시간·재장전·화면 진입 거리도 함께 기록한다. 한 웨이브 내내 눌러야 하거나, 적이 예고 없이 집 앞에 나타나는 배치는 제외한다.

### 6.3 성능과 가독성

현재 시제품은 활성 적80명·동시 투사체6개·웨이브 총84명 상한을 가진다. **성능이 검증된 수치가 아니라 폭증을 막는 임시 상한**이다. S21 Ultra에서 가로 화면·연속 웨이브·앱 복귀를 먼저 확인하고, 이후 하위 사양 기기로 범위를 넓힌다.

목표안은 정상 전투60fps, 물량이 많을 때도30fps 미만으로 장시간 내려가지 않는 것이다. 실제 프레임/발열/메모리는 미측정이다. 성능 저하 시 적 수를 더 늘리지 않고 스폰 분산·렌더링·자산 크기부터 수정한다. 겹친 상대가 한 덩어리로만 보이면 숫자 글자를 더 붙이지 말고 간격·실루엣·표시 밀도를 줄인다.

## 7. 화면·연출 전략

**표시할 것:** 적의 위치, 공의 궤적, 집 체력, 재발사 가능 상태, 현재 물건, 웨이브 종료.

**보여주지 않을 것:** 매 타격의 문장·대형 크리티컬 글자·중앙 연쇄 문단·상시 별 조건·장비 능력치 목록·긴 개그 대사.

| 장면 | 구성 원칙 |
|---|---|
| 전투 | 왼쪽 아빠/집, 넓은 중앙 탄도, 오른쪽 접근. 무기는2개만 크게 표시 |
| 조준 | 점선과 당기는 선. 설명은 첫 조작 때만 짧게 |
| 관통 성공 | 짧은 타격음·밀림·공의 궤적·작은 연속 수치 정도. 화면 가림 금지 |
| 실패 | 무엇이 집에 닿았는지 보인 후 재도전 버튼 하나를 우선 |
| 웨이브 종료 | 코인·강화 하나·다음. 전투 중의 정보를 정산 화면에서 읽게 함 |

초기 미술은 기존 병맛 만화 인물을 재사용한다. 치킨집용으로 선택했던 D 도트풍은 별도 운영 게임 시안이므로 이 게임에 자동 적용하지 않는다. 카메라·발사 위치·바닥선·캐릭터 방향을 먼저 고정한 뒤 던지기/대기/반응 포즈를 만든다. 새로운 원화 양보다 실제 해상도에서의 동작 일치를 우선한다.

## 8. 성장·코인·수익화

### 8.1 성장 최소안

초기에는 웨이브 사이 **강화 하나**만 제공한다. 현재 시제품은 관통 수와 일부 피해를 높이는 임시 강화이며 최대5다. 실제 장기 성장은 추가 물건 해금과 플레이 상황 변화가 맡도록 제안한다.

코인은 전투 보상으로 획득하고 강화/해금에 쓴다. 출시 후보에는 웨이브 완료 체크포인트와 영구 해금 저장을 제안하지만, 현재 시제품은 재시작 시 초기화되는 세션형이다. 저장·중복 보상 방지는 본제작 관문 뒤에 구현하고 검증한다.

가격은 ‘원하는 다음 물건을 얻기 위해 같은 쉬운 판을 얼마나 반복해야 하는가’로 평가한다. 첫 해금을 보여주려고 과도한 재화를 뿌리거나, 해금 전에 기본 물건을 무력화하지 않는다. 기존 도시락·등급·부위 장비 경제는 옮기지 않는다.

### 8.2 광고 수익화는 후속 검증

광고는 핵심 재미 검증 이후에 연결한다. 제안 후보는 웨이브 종료 보상 추가 수령, 선택형 임시 도우미/특수 물건 체험이다. 기본 조작·재시작·정상 진행을 광고로 잠그지 않는다. 웨이브 도중 강제 광고는 넣지 않는다.

특수 물건 횟수 제한과 광고 체험을 함께 쓰면 일부러 위기를 만들어 광고를 유도하는 설계가 되지 않는지 확인한다. 광고를 보지 않는 집단도 정상적으로 이길 수 있어야 한다. 광고 SDK·계정·정산·상용 ID는 이 시제품에 연결하지 않았다.

이 문서에는 예상 매출을 새로 제시하지 않는다. 광고 단가·D1/D7·유입 비용은 미확인이다. 기존 회사 전략 v2의 손익 시나리오를 이 게임의 실측 성과로 인용하지 않는다.

## 9. 제작 단계와 관문

| 단계 | 납품 범위 | 다음 단계로 넘어갈 조건 |

실제 플레이 영상의 **소재 반응 시험은 P1 직후**에도 소규모로 할 수 있다. 배포 준비 전 클릭/참가 신청을 설치 단가로 부르지 않는다. 일정·광고비 집행은 별도 승인한다. 코드 재사용 도구·범용 엔진·자동차 원화를 P0의 선행 조건으로 만들지 않는다.

## 10. 사람 테스트와 판단 기준 초안

숫자는 **내부 제안이며 사용자 승인 전**이다. 처음 하는 Android 이용자8명을 대상으로 소규모 관찰한다. 제작 과정을 이미 아는 사람만으로 구성하지 않는다. APK가 준비되기 전에는 모집·관찰 완료를 선언하지 않는다.

| 관찰 | 초기 지지 신호 | 실패/수정 신호 |
|---|---|---|
| 첫 조작 | 8명 중6명 이상이 말로 설명하지 않아도30초 내 발사 | 무기 버튼을 누르기만 하거나, 드래그 위치/방향을 반복 오해 |
| 줄 관통 이해 | 6명 이상이3명 이상 맞힌 장면과 이유를 설명 | ‘자동으로 된 것’으로만 인식하거나 맞은 수조차 알 수 없음 |
| 신발의 역할 | 5명 이상이 안내 뒤가 아닌 상황을 보고 신발→골프공 선택을 한 번 이상 사용 | 골프공만으로 항상 해결, 신발의 이점이 눈에 안 보임 |
| 반복 의사 | 5명 이상이 권유 없이 다음 웨이브 또는 재도전 | 결과 화면에서 이유 없이 종료하거나 강화를 강요로 느낌 |
| 화면 이해 | 집 피해 원인을6명 이상 설명 | HUD보다 적/투사체를 놓치거나, 효과가 적을 가림 |

이 표본으로 D1·수익성·대중적 흥행을 판정하지 않는다. ‘신발을 써보세요’라고 말한 뒤의 행동은 자발적 활용으로 세지 않는다. 같은 참가자의 재시험은 학습 효과가 있으므로 신규 참가자 관찰과 구분한다.

P1에서 모으기 가설이 실패하면 **배치·밀치기/감속·관통 수를 한 번씩 분리해 조정**한다. 두 번 조정 후에도 골프공 난사와 의미 있는 차이가 없으면 ‘모으기’를 강제하기보다 골프공 중심 게임으로 범위를 재검토한다. 실패를 감추려고 적/물건/보상을 추가하지 않는다.

## 11. 현재 구현·검증 상태

현재 코드와 수치의 기준은 [가로형 시제품 구현 기록](dad-landscape-throw-prototype-v1.md)이다. 전략 제안과 구현 수치가 충돌하면 구현 상태는 해당 기록/코드로 확인하고, 다음 변경을 별도로 기록한다.

- 씬: `Assets/DadThrowDefense.unity`, 모델/뷰: `Assets/DadSchoolBoss/ThrowDefense/`.
- 기존 본편 시작 씬과 Build Settings를 교체하지 않았다. 기존 APK에 자동 반영되지 않는다.
- 관리 코드 검사193개 통과: 기존169 + 신규 투척24. 첫 웨이브 승리 경로는 확인했지만 사람의 재미를 검증한 것은 아니다.
- Android 빌드 모듈이 없는 로컬 환경이므로 새 APK 미생성. Unity/플레이어/에뮬레이터 창 실행 없이 컴파일·관리 코드 검사만 했다.
- S21 Ultra 가로 회전·터치·실제 화면·성능·음향은 미검증. 현재 원화는 재사용/임시 자산이다.
- 진행 저장·추가 물건 구매·실광고·장기 콘텐츠는 아직 없다.

이 문서 작성에서는 추가 코드·에셋·프로젝트 설정을 변경하지 않는다. 기존 수정과 V20 작업은 보존하고 커밋·푸시하지 않는다.
