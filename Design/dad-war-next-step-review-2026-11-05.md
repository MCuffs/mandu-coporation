# 아빠 전쟁 — 다음 개발 검토

2026-11-05. 검토 기준: main `224abcf`. 기획서·코드·기존 봇 보고서를 대조했다. 이번 검토에서 Unity 실행, Android 설치, 새 사람 테스트는 하지 않았다. 아래는 개발 제안이며 사용자 확정 결정이나 구현 완료 기록이 아니다.

## 판단

**슬링샷 전투는 검증 가능한 형태까지 왔지만, 전투와 성장의 연결이 아직 끊겨 있다.** 60판·에셋·오프닝이 있다는 사실로 재미나 지속성을 판단할 수 없다. 다음 목표는 새 모드나 층 추가가 아니라 **처음 10판에서 ‘내가 의도해 쏨 → 좋은 결과를 이해함 → 장비/강화로 다음 발이 달라짐 → 다시 해 봄’이 이어지는 플레이**다.

기획의 중심은 이제 다음과 같다.

- 목표: 다가오는 상대를 아빠 몸으로 들이받고 벽·상대·공을 연결해 적은 발사로 정리한다.
- 경험: 진지한 아빠의 황당한 비행, 내가 만든 연쇄의 손맛, 다음 한 발이 달라지는 성장.
- 반복 결정: 지금 직선으로 쏠지, 벽으로 우회할지, 분노 발사나 상대 공을 어떻게 이용할지.
- 장기 동기 가설: 새 장비 효과, 별 3개 재도전, 다음 층의 새로운 공간 규칙.

판정은 **개연성은 있으나 사람의 재미·반복 행동은 미검증**이다. 보상 루프의 일부는 단순 미검증을 넘어 코드 연결이 빠져 있다.

## 2. 우선 보완 사항

### P0-1. 도시락 장비를 실제 발사에 연결

**확인:** `DadSlingshotBattle.ApplyGrowth`는 강화 배열·특수 발사 선택·패배 보정만 읽는다. `DadProgress.gearRarity/gearValue`는 반영하지 않는다. 반면 `DadHomeScreens`와 `DadSchoolRewards`는 장비 전투력과 “더 셈” 비교를 계속 보여준다.

**영향:** 핵심 보상인 도시락에서 뽑고 장착해도 전투가 같아진다. ‘성장하고 다시 한다’의 연결이 끊긴다.

**제안:** C-09를 가장 먼저 구현한다. 다만 첫 단계부터 6부위에 모두 새 액티브 기능을 만들지 않는다.

1. 먼저 손(충돌 전달)·신발(튕긴 뒤 속도 보존)의 두 효과를 작게 시험한다.
2. 같은 배치/같은 발사로 전후 차이를 볼 수 있게 한다. 테스트 장면은 개발 도구로 두고 새 게임 모드로 만들지 않는다.
3. 나머지 부위는 체력·벽꿍 등 제한된 수동 효과로 확장한다. 정확한 수치는 실험 후 정한다.
4. 비교 카드의 추상 전투력을 실제 효과/변화로 교체한다. 서로 다른 효과를 합친 임의 점수로 자동 장착을 결정하지 않는다.
5. 기존 `ResolvePending/OpenAll`의 value 대소 비교도 새 기준에 맞춘다. 효과가 여러 종류면 ‘모두 열기’가 기존 선택을 덮지 않도록 규칙을 먼저 정한다.
6. 이미 저장된 6슬롯의 등급/가치를 어떻게 새 효과로 변환하는지 명시한다. 기존 저장을 임의 삭제하지 않는다.

처음 10판에서는 의도한 효과를 보여 주는 장비를 보장하는 안이 적합하다. 무작위 18종보다 첫 장비 변화 한 번이 이해되는지 먼저 확인한다.

완료: 장착 전후 같은 조건의 전투 값과 결과가 바뀌고, UI 수치와 일치하며, 재실행 후 유지된다.

### P0-2. 무효 강화 차단과 강화 역할 분리

**확인:** `GrowthCapped`는 “최대” 표시만 한다. 강화 버튼은 코인 충분 여부만 보고, `DadProgress.TryUpgrade`도 상한을 검사하지 않는다. 들이받기 Lv.20·도움닫기 Lv.20·멀리 날리기 Lv.25 이후에는 해당 연속 보너스가 더 늘지 않는데 구매가 가능하다. 공유 비용은 총 강화 횟수에 따라 올라간다.

**제안:** 표시뿐 아니라 구매 로직도 같은 상한을 검사한다. 최대 버튼은 비활성화하고 코인과 다른 강화 비용이 변하지 않는지 확인한다.

또 `SlingshotSim`은 맞은 상대의 속도에 `knockBonus * throwBonus`를 곱한다. 들이받기와 멀리 날리기는 각각 +3%/+2%지만 작용하는 핵심 변수가 같다(멀리 날리기는 Lv.10 벽 피해 보너스 추가).

4종을 유지한다면 예를 들어 다음처럼 결과를 분리하는 안을 시험한다.

- 들이받기: 직접 충돌의 피해/무거운 상대에 대한 효과.
- 도움닫기: 우리 아빠의 발사 속도.
- 멀리 날리기: 맞은 상대의 전달 거리/벽 충돌.
- 체력: 실수 허용.

이는 채택 전 제안이다. 직접 피해가 정수인 현재 구조에서는 작은 %가 아무 변화도 못 만들 수 있으므로 단계별 문턱이나 누적 계산을 함께 설계해야 한다. 구별하기 어렵다면 3종으로 단순화하는 선택도 열어 둔다.

완료: 각 구매의 ‘현재→다음’ 실제 값이 보이고, 서로 다른 항목을 골랐을 때 플레이어가 차이를 설명한다.

### P0-3. Android에서 손맛과 보스 학습을 먼저 관찰

**근거:** 실기기 터치는 현재 보고서에서도 미확인이다. 에디터 마우스·봇은 손가락 가림, 화면 끝 당김, 실수 발사, 기기 발열/재개 문제를 대신하지 못한다.

첫 개발 빌드에 필요한 범위:

- 새 저장에서 스플래시→게임 시작→프롤로그→1-1→1-10.
- 조준 취소·두 손가락·화면 가장자리·앱 전환·뒤로 가기·소리 확인.
- 첫 조준선과 발사 방향의 이해, 쟁반의 정면/우회, 큰아빠의 3초 내 재충돌, 보스 그로기 원인.
- 짧은 한글과 결과 수치, 작은 적/얼굴이 실제 화면에서 식별되는지.

특히 빠르게 아무 방향으로 반복 발사해도 무적 비행 덕에 쉽게 이기는지 비교한다. `Hurt`는 비행 중 피해를 막는다. 이 규칙 자체는 의도지만, 무작위 반복 발사가 조준보다 유리하다면 핵심 선택이 약해진다. 현재는 가능성이지 확인된 악용법이 아니다.

### P1-1. 기록 재도전 동선

별/발사 수를 반복 목표로 삼지만, 승리 결과의 주 행동은 다음 판이고 홈은 `currentStage` 출발만 제공한다. 지난 판을 고르는 메인 UI는 확인되지 않았다.

**제안:** 큰 학교 지도 원화보다 먼저 결과에 `같은 판 다시`와 간단한 해금 판 목록을 제공한다. 각 판의 최고 별·최소 발사 기록을 보여주면 충분하다. 이미 있는 별 저장과 재플레이 보상을 사용하며 첫 클리어 보상 중복은 막는다.

완료: 별 2개로 깬 판을 다시 골라 도전하고 최고 기록만 갱신할 수 있다. 진행 스테이지가 의도치 않게 뒤로 이동하지 않는지도 확인한다.

### P1-2. 첫 10판의 ‘한 규칙씩’ 교육

`ForMain`의 순서는 사용할 만하다. 다만 짧은 화면 설명만으로 쟁반 우회·무거운 상대·보스 그로기를 동시에 익힐지는 모른다.

- 1-1: 반대 방향 당김과 취소.
- 1-2~3: 직접 만든 벽꿍과 연쇄.
- 1-4: 한 의자 상대의 예고와 발사 타이밍.
- 1-7: 쟁반 정면 실패를 안전하게 보고 옆으로 성공.
- 1-9: 공을 되받아치는 한 장면.
- 1-10: 두 번 맞히는 무거운 상대.
- 1-20: 졸개/공→그로기→직접 충돌의 연결.

새 대화창을 늘리기보다 배치와 포즈로 가르친다. 실패 때 실제 원인에 맞는 짧은 힌트를 주고, 첫 장비는 배우는 규칙과 연결한다. 봇 승률이 높다는 이유로 교육이 끝났다고 보지 않는다.

### P1-3. 급식실·체육관의 공간과 충돌 일치

긴 경기장 좌표는 1층 기준인데 2·3층은 옛 배경을 사용한다. 기획에도 상대가 뒷벽 위에서 나타나는 문제가 기록돼 있다.

**제안:** 1층 테스트가 먼저다. 2·3층 배경을 제작할 때는 좌우 튕김 선·상단 등장 문·바닥 시작·안전 영역을 공통 명세로 고정하고 원화와 충돌을 함께 검수한다. 카트/반발 매트까지 한 번에 추가하지 않는다. 새 공간 규칙은 각각 한 개씩 실제 발사 판단을 바꾸는지 시험한 뒤 늘린다.

### P1-4. 문서의 현재/과거 기준 분리

PM의 D-007/D-008은 B안인데 같은 문서의 2주 계획/관문은 손 떼기 강타·3D 시험을 요구한다. `first10-v2.csv`도 자동 펀치/강타 교육이다. 로드맵의 일부 에셋 표는 V13 이전 상태다. `dad-war-plan.md`의 큰아빠 28배 서술도 현재 8/10/12 체력과 다르다.

**제안:** 문서 전체를 새로 쓰기보다 현재 기준 표 하나를 두고, 폐기된 조작/일정/데이터에는 ‘구형·실행 입력 아님’을 표시한다. 특히 첫 10판은 코드에서 생성한 목록과 기획 목록을 대조할 수 있게 한다. 3D 전환과 추가 장르 검토는 이번 다음 단계에서 제외한다.

## 3. 이번 주 개발 순서 제안

기간은 인력과 빌드 환경에 따라 바뀌므로 날짜 확약보다 완료 조건으로 진행한다.

| 순서 | 납품 | 완료 기준 |
|---|---|---|
| 1 | 상한 구매 방지 + B안 기준 정리 | 무효 구매 없음. 기획/검사 목록이 B안으로 일치 |
| 2 | 손·신발 장비 효과와 카드 연결 | 같은 발사 비교에서 차이, 저장 유지. 추상 전투력 안내 제거 |
| 3 | Android 첫 10판 빌드 | 실제 터치/취소/앱 전환 동작 확인. 테스트 가능한 파일 확보 |
| 4 | 처음 하는 5명 내외의 관찰 테스트 | 설명 없이 무엇을 하는지 기록. 큰 오해부터 수정 |
| 5 | 같은 판 재도전과 간단한 판 선택 | 별/최고 발사 기록을 다시 노릴 수 있음 |
| 6 | 수정 빌드로 기존 G1/G2 검증 | 조작·의도한 연쇄·장비 변화·자발적 추가 판을 각각 판단 |

장비 개발을 기다리느라 터치 테스트를 미루지 않는다. 1~3은 가능한 범위에서 작은 단위로 진행하고 현재 빌드도 먼저 손으로 확인한다.

## 4. 가장 싼 사람 테스트

목적: ‘내가 쏜 결과를 이해하고, 변화된 한 발을 다시 써 보고 싶어 하는가’를 확인한다. 새 층·3D·광고 SDK·대량 원화는 제외한다.

초기에는 해당 조작을 처음 해 보는 Android 사용자 약 5명으로 큰 사용성 문제를 찾는다. 이 작은 표본을 리텐션 추정으로 쓰지 않는다. 이후 수정 빌드에서 기존 20명 관문을 B안 문구로 갱신해 검증한다.

관찰 전에 성공 방법을 설명하지 않는다. 막혀 도움을 주면 개입 시간과 내용을 별도 기록한다.

| 관찰 | 기록 | 실패 시 결정 |
|---|---|---|
| 처음 의도한 방향으로 쏘기 | 첫 성공까지 시도/오발/취소, 손가락 가림 | 당기기 기준점·손 안내·조준선 수정 |
| 벽꿍·연쇄를 의도했는가 | 쏘기 전 의도와 결과 뒤 설명. 우연 성공과 구분 | 배치/예측/결과 피드백 수정 |
| 장비 변화가 보이는가 | 동일 배치의 장착 전후, 무엇이 달라졌는지 | 효과 크기/명칭/구조 수정 |
| 쟁반·큰아빠·보스 대응 | 반복 실패 원인과 스스로 바꾼 행동 | 위험/방어 신호를 수정, 체력 증가로 해결하지 않음 |
| 스스로 더 하는가 | 권유 없이 다음 판/동일 판 재시작 | 전투 지루함과 보상 동선 문제를 나눠 확인 |
| 병맛이 전달되는가 | 먼저 반응한 장면, 기억하는 장면 | 대사보다 포즈/타이밍/대비를 보완 |

기존 내부 관문의 조작 16/20·의도한 벽꿍 설명 12/20·추가 판 12/20·장비 변화 인지 14/20은 B안으로 문구만 정확히 바꿔 유지할 수 있다. 이는 내부 진입 기준이며 시장 성공 기준이 아니다. 5명 관찰에 비율을 그대로 적용하지 않는다.

단순 반복 발사와 의도한 조준도 동일 성장 조건에서 비교한다. 전자는 쉬운데 후자만 힘들다면 압박·무적·발사 최소 세기·적 배치 중 원인을 분리한다. 장비 전후 비교에는 학습 순서 효과가 섞이므로 재시작/비슷한 배치를 활용하고 진행자의 칭찬을 성공 증거로 쓰지 않는다.
