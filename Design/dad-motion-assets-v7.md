# 움직임 연결 에셋 v7 — 디자인·애니메이션 참고 기준

## 목적과 범위

첫 제작 범위는 6장이다. 새 캐릭터를 늘리는 대신 기존 아빠·껌 짱의 이동 전환과 벽꿍 뒤 동작을 잇는다. 내장 image_gen으로 기존 프레임을 참조해 제작한다. 원본 PNG는 `Assets/DadSchoolBoss/Art/V7Motion/`에 저장한다.

이 문서는 앞으로 캐릭터 디자인·포즈 추가·애니메이션 연결 작업을 할 때 먼저 읽는 기준이다. 이번 작업에는 게임 코드 연결이나 전투 밸런스 변경을 포함하지 않는다.

## 원본 캐릭터 기준

- 아빠는 오른쪽을 향한다. 짧고 벗겨진 검은 머리, 피곤한 눈, 수염 자국, 올리브색 민소매 조끼, 크림색 속옷, 짙은 바지, 흰 줄이 있는 검은 슬리퍼를 유지한다.
- 껌 짱은 왼쪽을 향한다. 듬성한 머리와 수염, 금색 귀고리, 주황색 흰 줄 재킷, 얼룩진 크림색 속옷, 흰 줄이 있는 짙은 바지, 베이지색 쪼리를 유지한다.
- 걷는 껌 짱의 양손은 주머니 안에 둔다. 타격·낙하 반응에서만 꺼낸다.
- 기존 v5의 굵은 검은 외곽선과 단순한 면색을 따른다. 새로운 광택·역광·장식·의상·무기·글자를 추가하지 않는다.
- 기본 자세의 무심함을 유지하고 벽꿍 결과만 과장한다. 멋진 전투 영웅처럼 표정과 체형을 바꾸지 않는다.

## 재생 연결안

### 껌 짱 걷기

`기존 walk_0 → pass_a → 기존 walk_1 → pass_b → 반복`

신규 포즈가 기존 접지 포즈와 같은 자세로 보이면 중간 프레임으로 채택하지 않는다. 두 passing 포즈는 지지하는 다리가 서로 달라야 한다. 발의 지지점이 이동 방향과 맞는지 작은 화면에서도 확인한다.

기존 `EnemyAction()`은 `clock * 4`로 보행을 재생한다. 실제 연결 때는 적별 이동 거리 누적값으로 프레임을 선택한다. 정지 시에는 멈추고, 넉백·공중 이동은 걷기 위상에 더하지 않는다. 이미지는 프레임 수만큼 늘려도 이 타이밍 문제가 저절로 해결되지 않는다.

### 아빠 출발·정지

`idle → move_start(약 60~90ms) → 기존 walk 4프레임`

`walk → move_stop(약 80~120ms) → idle`

위 시간은 첫 튜닝용 가설이다. 입력 반응을 늦추지 않도록 물리 이동은 즉시 시작한다. 출발 포즈가 재생되는 동안 실제 이동을 막지 않는다. 다시 이동하거나 공격을 시작하면 정지 포즈는 즉시 중단한다. 짧은 방향 전환마다 출발·정지 포즈를 반복시키지 않도록 속도 임계값과 짧은 유예를 둔다.

### 벽 충돌·주저앉기

`기존 fly → 실제 벽 접촉 시 wall_hit(약 50~90ms) → crumple(약 150~250ms) → 퇴장`

주저앉기는 우선 제압된 적의 퇴장 동작에 쓴다. 생존한 적이 주저앉은 그림에서 바로 걷기로 복귀하면 다시 끊기므로, 생존 적에는 짧은 hit 회복을 쓰고 일어나기 포즈는 추후 필요 시 추가한다. 공중에 뜬 것만으로 wall_hit을 재생하지 않는다. 반대쪽 벽에서는 그림을 좌우 반전한다. 벽·사물함과의 접촉 위치도 함께 조정한다.

## 캔버스·정렬·임포트

- 기존 v5 서 있는 캐릭터의 기준은 768×768, 발 기준 (384,720), 일반 적 기준 신장 560px이다. 신규 생성 원본의 실제 해상도는 `manifest.json`을 따른다. 원본이 이미 768로 정규화되었다고 가정하지 않는다.
- 실제 연결 전에 기준 포즈와 겹쳐 머리 크기와 몸통 크기를 맞추고, 발 또는 바닥에 닿은 골반 위치를 맞춘다. 투명 여백을 몸 크기로 계산하지 않는다.
- 주저앉기는 서 있는 자세보다 낮아야 한다. 바운딩 박스 높이를 모두 같게 확대하면 머리가 커지므로 금지한다. 머리 크기와 원래 신체 비율로 배율을 정한다.
- 걷기에서 상체를 과하게 흔들거나 각 프레임의 중심점을 따로 잡지 않는다. 지지 발의 바닥선을 맞춘다. 공중 포즈에는 발 고정 대신 몸 중심을 이용한다.
- Alpha Is Transparency 켜기, Mipmap 끄기, Clamp, Bilinear. Sprite Single 또는 현재 Texture2D 렌더링 방식에 맞춰 임포트한다. 캐릭터 표시 크기 기준으로 512부터 확인한다.
- 이번 원본 보관 폴더는 기존 DadArt 로더에 자동 연결되지 않는다. 임의로 v5 Resources 폴더에 넣어 보행 프레임 개수만 늘리지 않는다. 명시적인 순서와 상태 전환을 연결한다.

## 디자인 작업 시 확인할 것

1. 이 문서와 기존 v5 기준 프레임을 함께 연다. 새로운 그림체로 처음부터 재해석하지 않는다.
2. 실제 게임의 작은 표시 크기에서 검수한다. 큰 원본에서만 자연스러운 동작은 통과시키지 않는다.
3. 기준 프레임과 교대로 보며 머리·귀·조끼 지퍼·바지 줄무늬·신발이 튀는지 확인한다.
4. 걷기 4장 순환, 출발·정지, 벽 충돌·퇴장을 각각 연속 재생한다.
5. 좌우 반전과 바닥 접촉, 캐릭터 겹침, 배경 합성을 확인한다. 외곽의 반투명 음영이 후광처럼 보이면 추가 정리를 한다.
6. 실제 입력·충돌 시점과 맞춘 뒤 채택한다. 생성 완료와 게임 내 부드러움 검증을 구분한다.

## 제작 기록

전체 프롬프트와 참조 경로는 `dad-motion-assets-v7-prompts.json`에 기록한다. 최종 파일별 출처·해상도·투명도·검수 메모는 원본 폴더의 `manifest.json`을 따른다.

### 납품·검수 상태

- 6장 모두 생성·프로젝트 저장 완료. 원본은 각각 1254×1254 RGBA PNG이며 투명 픽셀을 확인했다.
- 6장을 개별 확인했다. 껌 짱 걷기 중간 2장의 지지 다리가 다르고, 아빠 출발·정지 및 껌 짱 충돌·주저앉기 자세를 구분할 수 있다.
- 생성 원본을 리사이즈·알파 제거하지 않고 보존했다. 기존 v5 캐릭터와의 정확한 머리 크기·발 위치 보정은 아직 하지 않았다.
- 특히 wall_hit은 원본의 상단 위치와 크기가 걷기보다 크다. 같은 캔버스 크기라고 같은 배율로 바로 재생하지 않는다. crumple은 몸 전체 높이 대신 머리 크기로 맞춘다.
- 생성 이미지의 프레임 간 일관성은 수작업 애니메이션 수준으로 보장되지 않는다. 현재 상태는 디자인·연결 검토용이며, 연속 재생·Unity 합성·Android 실기기 검수는 연결 작업에서 수행한다.
- [전체 미리보기](dad-motion-assets-v7-preview.html)와 [에셋 묶음](dad-motion-assets-v7.zip)을 함께 제공한다.
