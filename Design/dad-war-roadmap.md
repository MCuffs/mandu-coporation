# 아빠 전쟁 — 개발·에셋 통합 로드맵 v1

작성: 2026-11-04, 게임사업 PM. 게임 개발과 디자인 에셋 제작을 같은 단계와 관문 위에 둔다. 어떤 에셋을 언제까지 만들어야 다음 개발이 막히지 않는지가 이 문서의 목적이다.

- 결정·위험·2주 상세 계획: [PM 운영 문서](dad-war-pm.md)
- 조작·경제·광고의 내용: [product v2](dad-war-product-v2.md)
- 이야기·인물: [dad-war-plan.md](dad-war-plan.md)
- 화면 디자인 단계(D0~D7): [디자인 로드맵](dad-war-design-roadmap-v1.md). 아래 각 단계에 배치했다.

**날짜는 가정이다.** 제작 인원(사용자 + AI 세션, 별도 개발·아트 인력 여부)과 11/18 3D 결정에 따라 다시 잡는다. 단계를 넘기는 기준은 날짜가 아니라 관문 조건이다.

## 1. 방향

1. **재미를 먼저 증명한다.** 각도를 잡아 상대 아빠를 날리고 연쇄시키는 손맛이 있어야 장비·광고가 의미를 가진다. 조작 검증 전에는 콘텐츠 수를 늘리지 않는다.
2. **에셋은 결정 뒤에 만든다.** G1(11/18)에서 당겨 쏘기 조작이 확정되기 전에는 새 캐릭터 원화를 늘리지 않는다. 3D 여부는 G2 이후 결정하고, 그 전까지는 2D로 만든다.
3. **한 판에서 기억할 장면을 화면에 남긴다.** 사물함 찌그러짐, 날아가는 아빠, 처리 완료 도장처럼 결과가 보이는 연출에 아트를 먼저 쓴다.
4. **광고는 재미가 확인된 뒤 선택형으로 붙인다.** 무광고로도 끝까지 깰 수 있어야 한다.
5. **한국에서 먼저 검증한다.** 개그는 글 없이도 통하게 만든다(대사가 없어도 상황이 읽히는 그림).

## 3. 단계별 상세

### 0단계 — 조작 검증 (11/5 ~ 11/18)

**11/4 변경(PM D-007):** 핵심 조작이 B안 "아빠를 당겨 쏘면 직접 날아가 튕기고, 상대 아빠들이 다가오는 방식"으로 바뀌었다. 4판 시제품과 규칙·검증은 [dad-war-slingshot-v1.md](dad-war-slingshot-v1.md)에 있다. 원래 계획한 손 떼기 강타(A0)와 3D 외형 시험은 이 단계에서 뺐다. 당겨 쏘기는 2D로도 성립하는 구조라 3D 결정은 G2 이후로 미룬다.

**개발**
- 앱 ID 확정(`com.manducorporation.dadwar` 제안). Unity 6.3 LTS 업그레이드는 별도 브랜치에서 하고 기존 검사 통과를 확인한다.
- 시제품 B 다듬기: 조준 슬로 배율·걷기 속도·발사 목표 수를 사람 테스트로 조정하고, [first10 CSV](dad-war-first10-v2.csv)의 상대 소개 순서로 1-1~1-10 배치를 만든다.
- Android 개발 빌드를 만들어 테스트 기기에 설치한다.

**디자인·에셋** — 기존 그림 재사용이 원칙이다.

| 필요 | 상태 | 비고 |
| --- | --- | --- |
| 조준 UI(고무줄, 첫 튕김까지 점선, 세기 %) | 시제품에 있음 | 사람 테스트 뒤 다듬기 |
| 날아가는 아빠 | 재사용 | `special_0`을 회전해 시험 중. 채택되면 비행·착지·벽 튕김 자세 필요 |
| 첫 조작 안내(손가락이 뒤로 당기는 그림) | 시제품에 있음 | B-1 첫 발 전에만 |
| 전투 HUD(얇은 상단 체력·발사 수, 경기장 전체 화면) | 시제품에 있음 | V12 `design-preview-v1` 02면과 같은 방향 |
| 세로 긴 화면(9:19.5) 대응: 배경·상단 바를 화면 끝까지 | 필요 | 지금은 위아래 약 15%가 빈 띠(코드 기준) |

**G1 (11/18)** — 20명 중 16명이 3판 안에 의도적으로 각도를 잡아 쏘고, 12명이 직접 만든 벽꿍·연쇄를 설명하면 통과. 같은 자리에서 「아빠의 잔기술」 레벨업 카드를 정리한다. B안에는 레벨업이 없으므로 빼는 쪽으로 제안한다.

### 1단계 — 첫 10판 완성 (11/19 ~ 12/9)

**개발**
- 첫 10판: [first10 CSV](dad-war-first10-v2.csv)의 배치와 교육 순서대로 만든다.
- 성장: 독립 강화 4종으로 v5의 공통 전투력 방식을 대체한다. 장비는 6부위·3등급에 3조합(벽꿍형·연쇄형·폭주형)을 넣고, 초기 도시락 3개는 수작업 교육 보상으로 둔다.
- 기타: 연쇄 폭주(5연쇄 → 3초), 결과 → 다음 판 동선, 저장 복구와 강제 종료 검사.

**디자인·에셋**

| 필요 | 2D 트랙 | 3D 트랙 |
| --- | --- | --- |
| 아빠 | 당기기(웅크림)·비행·벽 튕김·착지 자세 4장 | 모델, 공통 리그, 기본 애니메이션(대기·당기기·비행·벽 튕김·착지·피격·승리) |
| 지호 아빠(접근형) | 있음 | 모델·리그·애니(걷기·공격·피격·날아감·벽꿍·주저앉기) |
| 서연이 아빠(의자 돌진) | 있음 | G2 이후 |
| 민준이 아빠(쟁반) | 있음 | G2 이후 |
| 지호 큰아빠 | 지호 아빠 1.45배 재사용 | 스케일 재사용 |
| 복도·사물함 | 배경 있음, 찌그러짐 3단계 있음 | 복도 모듈, 사물함 3상태 메시 |
| 툰 셰이더·외곽선·그림자 기준 | — | 필요 |

공통으로 필요한 것:
- 장비 조합 3종 아이콘(벽꿍형·연쇄형·폭주형).
- 연쇄 폭주 효과(아빠 주변 3초). V12 `impact-fx-v1`의 충격·먼지를 벽꿍과 몸 충돌에 연결한다.
- 디자인 D1(색 토큰·버튼 눌림 상태), D4(장비 비교·강화 행)를 적용하고 작은 글자를 본문 18·보조 16으로 올린다.

**G2** — 20명 중 12명이 권유 없이 추가 판을 시작하고, 14명이 첫 장비 전후 변화를 알아채면 통과.

### 2단계 — 1층 완성·실기기 (12/10 ~ 1/6)

**개발**
- 1층 20판(11~20판), 층 보스 학부모회장(두 가지 공격, 졸개 맞히기 → 그로기 → 벽꿍).
- 보상 광고 테스트 SDK 3지점([ad placements](dad-war-ad-placements-v2.csv)). 콜백이 와야만 지급하고, 중복 지급을 막고, 실패 시 기본 보상을 유지한다.
- 이벤트 기록(v2 12.3의 15종), 설정(소리·진동·이야기 다시 보기·버전), 지도(출발 카드에서 열기), Play 내부 테스트 트랙.

**디자인·에셋**

| 분류 | 필요 | 상태 |
| --- | --- | --- |
| 보스 | 학부모회장 등장 자세(1초 이내 컷)와 공격 2종 신호 | 걷기·준비·돌진·그로기·광폭화 있음, 등장 자세 필요 |
| UI | 광고 제안 3종: 결과 "광고 보고 +코인", 엄마 전화 찬스 부활, 장비 체험 | `mom_call` 재사용. 광고 표식 아이콘·실패 안내 필요 |
| UI | 설정 화면, 홈 우상단 메뉴, 지도(층 배경·판 노드·보스 노드·별) | 필요. 지도 아이콘은 `tab_school` 재사용 |
| UI | 보스 등장 카드(이름표·한 줄 사연) | 필요(이름표 문구는 있음) |
| 소리 | 고무줄 당기기·발사 휘익, 벽 튕김, 사물함 찌그러짐 3단계, 보스 전용 음악, 엄마 전화 벨 | 필요. 기본 타격·벽꿍·연쇄·도시락은 있음 |
| 햅틱 | 벽꿍·보스 마무리 진동 패턴 | 필요 |
| 오프닝 | 문 열림·발소리 등 컷 효과음 | 필요(v11은 무음) |

디자인 D5(결과·광고), D6(모션·소리), D7(실기기 검수)이 이 단계에 들어간다.

**G3**
- 목표 Android 저사양 30fps, 중간급 60fps.
- 테스트 광고가 실제로 표시되고 보상이 정확하게 지급됨.
- 1시간 연속 플레이에서 오류·저장 유실 없음.

### 3단계 — 3층 완성·출시 준비 (1/7 ~ 2/3)

**개발**
- 2층 급식실: 쟁반에 이동 가능한 빈 급식 카트를 발사 경로로 쓰는 규칙, 급식 봉사 반장.
- 3층 체육관: 반발 매트로 튕김 각도를 쓰는 규칙, 체육 선생님.
- 결말 연출, 60판 이후의 반복 구조 결정(결말의 "옆 학교 도전장" 활용).
- 출시 서류: 개인정보 처리방침·Play 데이터 보안 양식, 연령 등급, "아동 대상 아님" 설정.

**디자인·에셋**

| 분류 | 필요 | 상태 |
| --- | --- | --- |
| 소품 | 급식 카트(정상·날아감·충돌), 반발 매트(대기·튕김) | 필요 |
| 상대 | 피구 아빠(`dodge`) | 그림 9장 있으나 전투에 미사용. 체육관 원거리 상대로 쓸지 결정 |
| 보스 | 급식 반장·체육 선생님 등장 자세 | 나머지 동작은 있음 |
| 이야기 | 결말 2컷, 단톡방 알림 틀 | 필요([요청서](dad-war-story-asset-request.md)) |
| 이야기 | 아들 외형 기준 | **충돌**: 요청서는 올리브 후드, v11 컷은 크림 티셔츠. v11 기준으로 통일 제안 |
| 이야기 | 지호(아이) 외형 기준 | 필요(결말에 등장) |
| 스토어 | 앱 아이콘 재검토, 피처 그래픽 1024×500, 세로 스크린숏 5~8장, 15~30초 영상 | 아이콘(v5)만 있음. 싸움 장면에 아이 넣지 않기 |
| 홍보 | 보스전 마지막 몇 초 공유 영상(의리 테스트 형식) | 기획 제안만 있음 |

**G4** — 내부 인원이 60판을 끝까지 깨고 무광고로도 막히지 않으면 통과. 스토어 등록 자료와 개인정보·등급 양식도 준비돼 있어야 한다.

### 4단계 — 한국 제한 배포 (설 연휴 이후)

- 고정 배정으로 무광고군·광고군을 나누고 난이도는 같게 둔다.
- 관찰 지표: 첫 전투 완료, 첫 강화, 첫 장비, 첫 실패 후 재도전, 1-10 도달, D1(설치 다음 현지 날짜).
- 광고군의 재도전율이 5%p 이상 낮거나 D1이 3%p 이상 낮으면 원인을 검토한다(v2 12.2).
- 에셋: 광고 소재 3~5종(세로 영상, 처음 3초에 "의리 테스트" 반응), 스크린숏 A/B.

**G5** — 무광고군의 잔존과 자발적 반복이 개선됐을 때만 확장(글로벌·추가 층·외형 상품)을 논의한다.

## 5. 역할과 작업 방식

| 역할 | 맡는 일 |
| --- | --- |
| 사용자 | 방향 결정, 관문 승인, 테스트 참가자 연결, 계정·스토어·광고 계정 |
| PM(Claude) | 이 로드맵·PM 문서, 테스트 설계와 결과 정리, 관문 자료, 에셋 요청서 |
| 개발 세션 | 조작·성장·광고·저장 코드, 검사 |
| 디자인 세션 | 원화·UI 시안·토큰, 에셋 manifest |

- 코드 파일은 한 번에 한 세션만 고친다. 세션마다 별도 worktree·브랜치를 쓰고, 커밋은 자기 파일만 한다.
- 에셋은 `Art/V*`(원본) → 검수 → `Resources`(런타임) 순서로 옮기고, manifest에 상태를 적는다. 그림 생성 완료와 게임 연결 완료를 같은 상태로 적지 않는다.
- 관문마다 이 문서의 단계표와 에셋 상태를 갱신한다.
