# Android 에뮬레이터 호환성 실측

2026-11-16. 판정: 일부 플레이 확인, 전체 호환성/출시 승인은 보류.

## Android16 / API36.1 / Google Play x86_64 / ARM64 번역 / 2GB / SwiftShader

GitHub 배포본 v0.3.1 ARM64 APK(SHA256 ff720a7496573affcb6054971bfb0ec16ace10cfdd49112f0c78c369d9be9b04)를 그대로 설치했다. 앱 로그에서 Unity6000.1.5f1·IL2CPP arm64-v8a를 확인했다. Android 최초 전체화면 안내를 닫은 뒤 타이틀 → 대소동 → 터치 당기기/추가 돌진을 실행했고 화면에서 발사1/2·남은2명·연쇄1을 확인했다. 홈으로 나갔다 돌아오면 일시정지 화면이 표시됐다. 고정1080×2400에서 비행기 모드로 강제종료/재시작 후 타이틀도 확인했다.

화면 크기를720×1280으로 동적 변경하고 재시작했을 때 검은 화면 대기가 관찰됐다. 원래1080×2400으로 복원한 뒤 재실행에서는 최종 타이틀이 표시됐다. 최초 검은 프레임만으로 영구 정지라고 판단할 수 없으며, 지연이 길어 시작 상태 표시와 추가 성능 조사가 필요하다. 정확한 첫 프레임 시간/FPS는 측정하지 않았다. ARM 번역·2GB·가상 GPU가 포함돼 실물 휴대폰 성능 수치로 사용할 수 없다. 게임 PSS 관찰값 약263MB이며 이것을 모든 기기의 메모리 상한으로 해석하지 않는다.

## Android8.0 / API26 / x86_64 / 2GB

이 이미지에는 ARM64 번역이 없어 같은 게임 소스의 CPU 변형(ARM64+x86_64)을 별도로 빌드했다. 배포 ARM64 APK 그 자체의 실행 검사가 아니다. 소스 변경은 없고 아키텍처만 늘렸으며 개발용 빌드 스크립트는 Tools/DadCompatibilityBuild.cs.txt에 보존했다. 빌드 오류0/경고13.

SwiftShader 기본 환경은 GLES2를 광고해 Unity의 하드웨어 경고와 Graphics API 초기화 실패가 발생했다. 이는 요구 GLES3을 만족하지 않는 가상 환경으로 통과/실물 S7 실패의 근거로 쓸 수 없다.

호스트 GPU(AMD RX6600), GLESDynamicVersion을 켜 GLES3.1로 다시 실행했다. 타이틀 버튼과 대소동 UI까지 진입했으나 캐릭터·배경이 검게 나와 시각 검수는 실패했다. 구형 에뮬레이터 그래픽 드라이버·텍스처 지원의 영향인지 게임/엔진 문제인지는 아직 분리하지 못했다. 앱 로그에 Android13 전용 OnBackInvokedCallback 클래스 로드 경고가 있지만 이후 Unity가 시작됐으므로 그것만으로 정지 원인을 확정하지 않는다. 초기 시스템 서비스의 부팅 오류도 앱 크래시와 구분했다.

## 결론과 다음 관문

- 실제 Android 환경에서 한 판 조작과 제압이 확인됐다. Windows 검사만 수행했던 상태에서 진전한 것이다.
- Android8 시각 문제와 시작 대기를 남은 문제로 기록한다. S7 실기기/삼성 GPU는 미검증이며 출시 NO-GO를 유지한다.
- 이후 GLES3을 정상 제공하는 Android8 실물 또는 다른 가상 GPU에서 텍스처 형식/셰이더를 비교하고 초기 로딩 진행·실패 표시를 추가한다.
- 실제 보상 광고 완료·구매·D1은 검사하지 않았다. 테스트를 리텐션으로 집계하지 않는다.
- 창 없이 ADB 입력·로그·스크린샷으로 검사했으며 작업 종료 후 두 에뮬레이터와 작업 전용 라이선스 클라이언트를 종료했다.
