검수일: 2026-11-09 (한국 시간). 대상 소스: `58c0733`, 추가 돌진/대소동8판을 포함한 작업 사본. **판정: NO-GO — 일반 판매와 광고 상용 출시 보류. 제한된 내부 테스트만 가능.**

## P0 — 출시 전에 반드시 해결

### R-01. 정상 백업이 있는데도 진행이 초기화되는 저장 복구

**재현 완료, Unity 네이티브 검사 실패.** `DadProgress.Load()`는 JSON에서 객체가 만들어지면 유효한 저장으로 간주한다. 원본이 `{}`이면 정상 백업을 선택하지 않는다.

재현 절차:

1. 임시 저장에 코인123을 저장하고 정상 `.bak`을 만든다.
2. 원본 파일만 `{}`로 바꾼다.
3. `DadProgress`로 다시 읽는다.
4. 기대값123, 실제0. 정상 백업이 무시된다.

사용자의 실제 파일에 이 절차를 적용하면 안 된다. 이번 검사는 임시 파일에서 수행했다. 원본·백업·tmp 각각의 구조·버전·필수 정보와 수치 범위를 검증한 뒤 후보를 선택해야 한다. 기존 v1/v2 최소 저장의 호환성도 유지해야 한다. 실패한 원본을 정상 백업 위로 다시 저장하는 경로도 막아야 한다.

수정 완료 기준: 이번 재현 검사 통과, 기존 손상 문자열·원본 유실·완성된tmp·이전 저장 호환·복구 후 재저장 검사 통과. 완전한 복구 실패 시 조용한 초기화 대신 사용자에게 복구 실패를 알리는 동작 검수.

### R-02. Android 앱 ID가 잘못된 형식

ProjectSettings에는 Standalone 기본값만 있지만, **Unity API로 실제 Android ID를 조회한 결과는 `com.SecondFistStudio.`**였다. 빈 마지막 구간을 포함해 Android ID 규칙과 맞지 않는다. 회사 표시도 현재 `SecondFistStudio`다.

Android ID를 명시적으로 확정하고 조회값·최종 merged manifest·설치 패키지에서 같은 값을 확인해야 한다. PM의 후보는 `com.manducorporation.dadwar`이며 아직 현재 설정에 적용된 값은 아니다. 게시 후 ID 변경은 다른 앱으로 취급되므로 첫 출시 전에 고정한다. [Android 공식 ID 규칙](https://developer.android.com/build/configure-app-module)

완료 기준: 유효한 명시 ID, 회사명/버전 정리, 실제 AAB/APK의 ID와 서명 확인. 키스토어 비밀을 저장소나 검수 로그에 올리지 않는다.

### R-03. 현재 Android 빌드 구성이 출시 요건을 충족하지 못함

실제 조회 결과는 Unity2021.3.2f1, Mono2x, ARMv7 단독, Target SDK Automatic이다. 빌드 모듈은 **현재 설치됨**. 해당 설치의 SDK 플랫폼은 API29·30뿐이다. 과거 문서의 ‘Android 모듈 없음’은 현재 환경과 다르다.

2026-08-31 이후 일반 Android 신규 앱/업데이트는 API36 이상 대상이 필요하다. ARM64 및 최종 네이티브 라이브러리 검증도 필요하다. [목표 API 공식 기준](https://developer.android.com/google/play/requirements/target-sdk), [64비트 공식 기준](https://developer.android.com/google/play/requirements/64-bit)

설치 엔진은 기존16KB 지원 패치 기준보다 오래됐다. 16KB 호환성을 설정 숫자만으로 승인하지 않는다. 현재 공식 안내의16KB 호환 요구와 2027-02-01 업데이트 제한 안내를 구분해 확인하고, 최종 네이티브 라이브러리/산출물과16KB 기기에서 검증해야 한다. [16KB 공식 안내](https://developer.android.com/guide/practices/page-sizes)

완료 기준: 별도 업그레이드 사본에서 지원 중인 Unity LTS·적합한 SDK/NDK/JDK·ARM64 구성, 기존 회귀 통과, 서명된 AAB와 테스트 APK 생성, 새 설치/업데이트/복귀/오프라인 실행 및 Play Console 사전 검사 확인. 현재 작업 사본에 검증할 APK/AAB는 없었다.

### R-04. 개인정보 고지와 스토어 제출 준비

소스와 설정 UI에서 개인정보 처리방침 진입점을 찾지 못했다. Play Console의 Data safety·콘텐츠 등급·대상 연령·서명 설정은 접근하거나 검증하지 않았다. 이 항목을 완료로 표시할 근거가 없다.

Google Play는 앱 내 개인정보 처리방침과 Console 링크·정확한 Data safety 신고를 요구하며, 개인정보를 수집하지 않는 앱도 처리방침 제출 대상이라고 안내한다. 실제 SDK·수집 항목에 맞춘 공개 문서와 연락처를 준비해야 한다. [공식 User Data 정책](https://support.google.com/googleplay/android-developer/answer/10144311)

완료 기준: 앱 내 동작하는 고지 링크, 실제 데이터 흐름과 일치하는 신고, 대상 연령·등급·스토어 자산 확인. 현재 계정 생성 기능이 없는 제품에 계정 삭제 기능이 필수라고 단정하지 않는다.

## P2 — 개발 일관성

신규 체크아웃 임포트 시 `DadV5AssetImport` 규칙이 V14/V17 텍스처18개의 저장된 메타 설정을 변경했다. 단순 공백 외 textureType·압축·일부 최대 크기도 달랐다. 재현 증거는 `ReleaseAudit-2026-11-09/importer-drift.json`. 임포트 규칙을 최종 기준으로 삼고 메타를 정규화해 플랫폼별 결과 차이를 줄여야 한다. 현재 검사 통과를 ‘기존 메타 설정 그대로 검증했다’고 읽으면 안 된다.

백업만으로 기기 교체·삭제 후 복구를 제공하는 것은 아니다. 서버 저장/클라우드 동기화는 현재 없음. 오프라인 제품의 필수 기능이라고 단정하지 않되, 구매자에게 제공할 복구 범위와 고객 지원 경로를 명확히 한다.

## 판매 승인 관문과 다음 작업 순서

1. R-01 저장 복구를 먼저 수정하고 회귀 검사 재실행.
2. R-02/R-03 앱 ID·엔진·Android 빌드 구성 확정 후 서명된 실제 산출물 확보.
3. 저사양/중간급 Android에서 첫10판·후반 보스·대소동8판·홈 복귀·20분 연속 플레이. 터치 취소·앱 전환·백그라운드 종료·저장 재시작을 확인하고 충돌/ANR·프레임 시간·메모리·발열 기록.
4. Q-01 화면비 수정과 새 모드의 실제 렌더링·음향·접점 검수.
5. 기존 계획의 첫 사용자20명 관찰을 현재 돌진 방식에 맞춰 수행. ‘의도한 추가 돌진’, ‘설계한 연쇄’, ‘권유 없는 재도전’을 기록. 내부 가설 숫자를 매출 보장으로 사용하지 않음.
6. 광고 기반으로 갈 경우 테스트 광고·보상 회귀와 개인정보/스토어 신고를 함께 완료. 유료 다운로드라면 가격과 구매 기대에 맞춘 콘텐츠·지원 범위를 별도로 검증.
7. 모든 R 항목을 닫고 실제 산출물·기기 결과·사람 관찰 자료를 첨부한 재검수에서 판매 여부 재판정.

이번에는 ‘출시 가능’이나 ‘상업성 검증 완료’를 승인하지 않는다. 진행 가능한 다음 단계는 **저장 결함 수정과 Android 테스트 빌드 준비**다.
