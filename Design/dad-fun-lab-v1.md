# 핵심 재미 실험 3판 — 2026-11-09

기존 메인 게임과 저장·강화·도시락을 보존하고 별도 장면을 추가했다. 이번 목적은 새 콘텐츠 양산이 아니라 무엇을 계속 개발할지 판단하는 것이다. 세 실험은 정지한 상대·체력 1·한 발 조건으로 복잡한 성장 변수를 제거했다. 캠페인 밸런스에 그대로 이식하지 않는다.

## 실행과 조작

Unity에서 `Assets/DadFunLab.unity`를 직접 열거나 `Dad School Boss > Fun Lab > Open Three Experiments`를 선택한 뒤 Play. 빌드 시작 장면은 변경하지 않았다. 메뉴는 사용자가 선택할 때만 장면을 열며 자동 실행하지 않는다.

- 상단 1·2·3번 버튼으로 실험 선택. 화면을 뒤로 당겨 놓으면 한 번 발사한다.
- 1번: 쟁반 정면을 피하고 벽 반사로 모인 세 상대를 제압한다.
- 2번: 청회색 급식 카트를 밀어 네 상대를 제압한다. 카트는 실험용 단순 도형이다.
- 3번: 비행 도중 원하는 위치를 한 번 탭하면 그 방향으로 추가 돌진한다. 발사 뒤에도 경로를 선택할 수 있다.
- 하단 다시 버튼으로 즉시 초기화. Escape·정지 버튼으로 중단. 앱 포커스 상실 시 자동 정지하며 복귀 후 직접 재개한다.
- 짧은 당김·터치 취소는 발사하지 않는다. 기존 저장과 실험 결과를 연결하지 않는다.

## 실제 수행한 검증

화면을 자동으로 띄우지 않는 프로젝트 지침에 따라 **Unity/독립 플레이어 창을 실행하지 않았다**. 직접 마우스·손가락으로 조작하거나 애니메이션·음향을 시청한 결과는 없다. 아래는 실제 C# 모델에 방향·세기·시간 입력을 넣어 끝까지 진행한 프로그램 전략 시험이다. 사람의 재미·성공률·잔존율로 해석하면 안 된다.

재현 명령: `python Tools/check_dad_fun_lab.py` (Windows 설치 Unity의 Mono 이용). 다른 설치 경로는 `DAD_UNITY_DATA` 환경변수로 지정한다. 실행 보고서는 `dad-fun-lab-playchecks.txt`.

| 시험 | 관찰 |
| --- | --- |
| 각도 2도 간격 × 세기 60/100/150, 각 판 540회 | 1번 7개·2번 27개·3번 0개의 일반 발사 성공 경로 |
| 같은 각도·세기에서 카트 켜기/끄기 | 카트 때문에 실패가 성공으로 바뀐 경로 4개. 예: 274도·세기150, 카트 명중4명 |
| 3번 발사 각도·돌진 시점·돌진 방향 탐색 | 추가 돌진 때문에 실패가 성공으로 바뀐 경로 24개. 예: 220도 발사, 0.4초 후 330도 돌진 |
| 3번 첫 발사 230~260도, 6개 시점에 가까운 생존 상대 방향으로 돌진 | 성공 14/96. 타이밍과 대상 선택에 따라 결과가 다름 |
| 회귀 검사 | 기존 규칙·난이도 및 새 규칙 합계161개 통과. 첫 발사 전 돌진 거절, 1회 제한, 재시작 초기화 등 |

좌표는 오른쪽0도·아래90도·위270도다. 탐색은 제한된 이산 입력만 사용하며 해법 전체를 증명하지 않는다. 자동 시험에는 화면 판독·터치 지연·사람의 판단 시간이 없다. 카트 연쇄는 실험 전용 단순 충돌로 구현했고 적 AI는 정지했다. 입력·렌더링·실기기 성능은 별도 검수가 필요하다.

## 설계 판단

**1순위 후보: 추가 돌진.** 발사 후 구경하던 구간에 한 번의 판단을 만든다. 같은 첫 발사의 성공 여부를 두 번째 선택으로 바꿀 수 있다는 근거가 있다. 단, 일반 발사만으로 성공 경로를 찾지 못한 3번 판은 돌진의 유용성을 확인하기 위한 의도적 배치다. 이를 기능 자체의 재미가 증명됐다고 해석하지 않는다. 다음에는 첫 명중 직후 돌진을 자연스럽게 알아채는지, 조작이 바쁘거나 답답하지 않은지 실제 화면에서 확인한다.

**보조 후보: 카트.** 아빠 이외의 물체를 목표로 삼을 이유가 생겼다. 지금은 정해진 줄을 쓸어버리는 기능이므로 반복하면 정답 누르기로 끝날 수 있다. 카트 수량을 늘리기 전에 두 방향 중 하나를 선택하는 배치 한 판을 시험한다.

**보류: 정밀한 한 발 퍼즐을 메인으로 채택.** 첫 배치를 조밀하게 수정했지만 성공 경로는 제한적이다. 전체360도 탐색의 성공 비율은 사람 난이도가 아니지만, 초기 캐주얼 플레이에서 미세 각도 반복을 요구할 위험이 있다. 선택형 도전으로 남기고 실패 시 정답을 강요하는 방식은 피한다.

현재 결론은 ‘재미있는 게임 완성’이 아니라 **추가 돌진을 우선 검증할 이유를 확보**한 것이다. 다음 의사결정은 짧은 실제 플레이에서 설명 없이 재조준하는지와, 실패 후 자발적으로 다시 시도하는지를 관찰한 뒤 한다. 이번 단계에서는 광고·성장·더 많은 층을 추가하지 않는다.

## 적용 요청과 후속 관문

개발자는 우선 이 별도 장면만 실행한다. `DadFunLab.cs`는 입력·표시, `DadFunLabModel.cs`는 카트·돌진·실험 배치, `Tools/DadFunLabRunner.cs`는 재현 입력이다. 기존 `SlingshotSim`의 전투 수치는 변경하지 않았다. 실험용 코드의 메인 장면 연결은 아직 요청하지 않는다.

실행 검수는 한글·세 버튼·좌우 반사·당김 취소·돌진 1회·앱 전환 정지·재시작·카트 연쇄를 확인한다. 9:16/긴 화면·휴대폰에서의 실제 손 조작 결과를 기록한다. 이 관문을 통과한 후에만 추가 돌진의 전용 모션·타이밍 표시와 캠페인 시험판을 만든다.
