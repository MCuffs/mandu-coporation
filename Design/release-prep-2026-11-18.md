## 5. Android 시험 빌드 결과

던지기 게임을 플레이가 새 앱에 요구하는 모양으로 처음 빌드했다. [빌드 기록](dad-throw-android-test-build.txt), [산출물 검사](dad-throw-android-test-artifact.json).

| 항목 | 값 |
| --- | --- |
| 에디터, 방법 | Unity 6000.1.5f1, 창 없이, `DadThrowAndroidBuild.TestApk`(별도 사본 `C:\Users\user\DadWarWebGL`) |
| 모양 | 64비트(ARM64)만, IL2CPP, 최소 API 24, 타깃 API 36, 가로 |
| 크기 | **30.4MB**(11/11의 세로 본편 시험 빌드는 그림을 그대로 넣어 수백 MB였다) |
| 빌드 시간 | 4분 39초 |
| 산출물 검사 | **7개 통과**: 64비트 단독, 모든 네이티브 라이브러리 16KB 정렬, 플레이어 데이터, 앱 ID, 타깃 API 36, zipalign 16KB, 서명 검증 |
| 서명 | 디버그 키. 스토어에 올릴 수 없다 |
| 앱 ID | 시제품용(`com.manducorporation.dadthrow.prototype`). 다른 것과 나란히 설치된다 |
| 파일 | `C:\Users\user\DadWarWebGL\Builds\ThrowAndroid\DadThrow-arm64-test.apk` |

**이 빌드에서 알게 된 것:**

- **광고 SDK와 광고 ID 권한이 들어 있다.** 프로젝트에 광고 패키지가 있어서 던지기 게임이 부르지 않아도 딸려 들어간다(권한: `AD_ID`, `ACCESS_ADSERVICES_*`). 이대로 올리면 데이터 보안 신고의 "수집 없음"이 사실과 다르다. 광고 없이 올리려면 빌드에서 패키지를 빼야 한다(2절의 "광고 패키지 빼기").
- 빌드 기록의 "Android dependency resolution: False"는 광고 라이브러리 정리 도구가 템플릿 파일을 못 찾았다는 뜻이다. 빌드는 성공했지만, 광고 SDK가 반쯤 들어간 상태라 **기기에서 켜지는지는 확인되지 않았다.**
- **기기에 설치하거나 실행해 보지 않았다.** 연결된 기기가 없다. 사용자의 휴대폰에 이 파일을 넣어 설치하면 첫 실기기 확인이 된다.

**새 앱 ID로 만든 시험 번들(같은 날 밤).** 플레이가 받는 모양(AAB)에 `com.bluemushroom.dadwar`를 넣어 디버그 서명으로 만들었다(`DadThrowAndroidBuild.TestBundle`). [빌드 기록](dad-throw-android-test-bundle-build.txt), [산출물 검사](dad-throw-android-test-bundle-artifact.json).

| 항목 | 값 |
| --- | --- |
| 크기, 빌드 시간 | 30.1MB, 1분 45초 |
| 산출물 검사 | **6개 통과**: 64비트 단독, 16KB 정렬, 플레이어 데이터, 앱 ID, 타깃 API 36, bundletool의 번들 구조 검증 |
| 서명 | 디버그 키. 플레이는 받지 않는다. 사용자의 업로드 키로 서명하면 올릴 수 있는 모양이 된다(7절) |

**광고 자리가 들어간 시험 APK(같은 날 밤).** 광고를 넣기로 한 뒤 같은 방법으로 다시 만들었다. 30.4MB, 3분 8초, 산출물 검사 7개 통과, 광고 라이브러리 정리 성공. 파일 위치는 위와 같다. **휴대폰에 설치하면 4번째 판부터 시험 광고 버튼이 나와야 한다. 아직 설치해 보지 않았다.**

**플레이 콘솔에 앱 만들기(같은 날 밤).** 사용자가 가입을 마친 뒤 PM이 "앱 만들기" 화면에 앱 이름(아빠 전쟁), 패키지 이름(사용 가능 확인됨), 기본 언어(한국어), 게임, 무료를 넣어 두었다. 선언 세 가지(개발자 프로그램 정책, Play 앱 서명 약관, 미국 수출법)에 동의하고 "앱 만들기"를 누르는 것은 사용자가 한다.

## 6. 순서 (날짜는 약속이 아니다)

1. 사용자: D-U-N-S 다시 넣기 → 가입 마치기. 결정 2번(앱 ID).
2. PM: 처리방침 고치기, 광고 패키지 빼기, 게임 안 링크. 사용자: 업로드 키 만들기.
3. PM: 서명한 AAB. 사용자: 휴대폰에 설치해 확인.
4. 사용자: 앱 만들기, 등록정보·설문 제출, 내부 테스트 시작. 그림 요청: 아이콘과 대표 그림.
5. 사람 5~8명이 해 본 기록을 보고 공개 범위를 넓힐지 정한다.
6. 앱인토스: 휴대폰 실측 → 콘솔 등록 → SDK → 등급 정보 → 심사.

## 7. 업로드 키와 스토어용 번들 (사용자가 직접)

키와 비밀번호는 사용자만 안다. PM은 만들지도, 보지도, 저장소에 적지도 않는다.

**키 만들기(한 번만).** 저장소 밖의 폴더에 만든다. 비밀번호 두 개(키 저장소, 키)와 이름·조직을 묻는다. 만든 파일과 비밀번호는 따로 백업한다.

```
"C:\Program Files\Unity\Hub\Editor\6000.1.5f1\Editor\Data\PlaybackEngines\AndroidPlayer\OpenJDK\bin\keytool.exe" -genkeypair -v -keystore C:\Users\user\keys\bluemushroom-upload.jks -alias upload -keyalg RSA -keysize 2048 -validity 10000
```

**스토어용 번들 만들기.** 같은 터미널(PowerShell)에서 네 값을 넣고 빌드를 시작한다. 터미널을 닫으면 값은 사라진다.

```
$env:DAD_UPLOAD_KEYSTORE = "C:\Users\user\keys\bluemushroom-upload.jks"
$env:DAD_UPLOAD_KEY_ALIAS = "upload"
$env:DAD_UPLOAD_KEYSTORE_PASS = Read-Host "keystore password"
$env:DAD_UPLOAD_KEY_PASS = Read-Host "key password"
& "C:\Program Files\Unity\Hub\Editor\6000.1.5f1\Editor\Unity.exe" -batchmode -nographics -projectPath C:\Users\user\DadWarWebGL -buildTarget Android -executeMethod DadThrowAndroidBuild.StoreBundle -logFile C:\Users\user\DadWarWebGL\Logs\android-store-bundle.log
```

결과는 `C:\Users\user\DadWarWebGL\Builds\ThrowAndroid\DadWar-<버전>-<코드>.aab`와 `Design/dad-throw-android-store-bundle-build.txt`에 나온다. 값이 하나라도 빠지면 빌드는 시작하지 않고 무엇이 빠졌는지만 적는다.

- 올리기 전에 광고 패키지를 뺄지(1절 결정 3)가 먼저 정해져야 한다. 지금 그대로 만들면 광고 SDK와 광고 ID 권한이 들어간다.

## 8. 광고 (11/18 밤, 사용자 "광고 넣어서")

**넣은 것은 보상형 광고 한 자리다.** 세로 본편 때 정한 광고 원칙(11/10)을 그대로 따랐다.

| 원칙 | 던지기 게임에서 |
| --- | --- |
| 선택해서 보는 광고만 | 판을 깬 뒤 결과 카드 아래에 "광고 보고 +N원 더 받기" 버튼. 누르지 않으면 아무 일도 없고 "다음"은 그대로 눌린다 |
| 처음에는 권하지 않는다 | 첫 세 판(1-1~1-3)에는 버튼이 없다. 4번째 판부터 나온다 |
| 진 직후에 권하지 않는다 | 패배 카드에는 없다. 오늘의 도전조에도 없다(자체 보너스가 있다) |
| 끝까지 본 사람에게만 | 광고 SDK의 "보상 획득" 신호에만 준다. 중간에 닫으면 주지 않는다. 한 번의 클리어에 한 번만 준다 |
| 남발하지 않는다 | 광고 한 번 뒤 30초 쉬고, 한 번 켠 동안 5번까지(본편과 같은 장치) |
| 배너, 강제 전면 광고 | 없다 |

- 주는 양은 그 판에서 번 돈만큼이다(두 배가 된다). 숫자는 처음 잡은 값이다.
- 광고가 준비되지 않았으면 버튼이 아예 나오지 않는다. 광고가 떠 있는 동안에는 게임의 어떤 버튼도 눌리지 않는다.
- 정지 화면에 "개인정보처리방침" 링크를 넣었다. 법이 요구하는 지역에서는 그 아래에 "광고 개인정보 선택 변경"도 나온다.
- Android에서 게임을 켜면 광고 동의 절차(UMP)와 광고 불러오기가 뒤에서 시작된다. 이 부분은 세로 본편 때 만든 코드가 그대로 돈다.
- 창 없는 검사 522개 통과(광고 6개 추가). Unity에서 가짜 광고로 [화면 5장](dad-throw-ad-captures-2026-11-18/)을 찍어 확인했다.

**아직 아닌 것:**

- **실제 광고가 뜨는 것은 한 번도 보지 않았다.** 에디터에서는 가짜 광고로만 확인했다. 휴대폰에서 시험 광고가 뜨고, 끝까지 보면 돈이 들어오고, 닫으면 안 들어오는지 봐야 한다.
- 광고 ID가 Google의 시험용이다. 실제 수익은 AdMob 계정과 광고 단위가 생긴 뒤다(사용자).
- ~~처리방침 본문이 아직 세로 본편 기준이다.~~ 같은 날 밤에 고쳐 사이트에 올렸다. 스토어 신고 초안도 광고가 있는 것으로 고쳤다([초안](store-listing-draft-v1.md) 3절). 실제 광고 ID로 바꾸면 "출시 전 시험 버전에서는 시험용 광고가 나온다"는 문장을 다시 본다.
- 광고가 사람을 더 남게 하는지, 떠나게 하는지는 모른다.

## 9. 플레이 콘솔 앱 설정에 넣은 값 (11/18 밤, 사용자 "네, 채워 주세요")

사용자의 Chrome에서 PM이 콘솔을 조작해 넣었다. 약관 동의, 최종 제출, 게시는 하지 않았다. 대시보드의 "앱 설정" 12개 가운데 10개가 끝났다.

| 항목 | 넣은 값 | 상태 |
| --- | --- | --- |
| 개인정보처리방침 | 사이트의 처리방침 주소 | 저장 |
| 로그인 세부정보(앱 액세스) | 제한된 부분 없음("아니요") | 저장 |
| 광고 | 광고 있음("예") | 저장 |
| 타겟층 | **만 18세 이상만**(사용자 선택). 미성년자 사용 제한 옵션은 켜지 않았다 | 저장 |
| 데이터 보안 | 아래 표 | 저장 |
| 정부 앱 | 아니요 | 저장 |
| 금융 기능 | 제공하지 않음 | 저장 |
| 건강 | 건강 기능 없음 | 저장 |
| 판매자 상태 | 적용("예", 사용자 확인). 서비스 약관 주소는 비움 | 저장 |
| 앱 카테고리와 연락처 | 게임 > 캐주얼. 태그: 물리 기반, 아케이드, 액션, 캐주얼, 타워 디펜스. 조직 이메일과 개발자 웹사이트. 전화번호는 비움 | 저장 |
| 스토어 등록정보 | 간단한 설명, 자세한 설명, 휴대전화 스크린샷 8장 | **초안으로만 저장.** 아이콘(512)과 대표 그림(1024×500)이 없어 마칠 수 없다 |
| 콘텐츠 등급 | 문의 이메일과 카테고리(게임)까지 | **멈춤.** IARC 약관 동의 체크는 사용자가 한다 |

**데이터 보안에 넣은 답:**

| 문항 | 답 |
| --- | --- |
| 필수 사용자 데이터를 수집하거나 공유하나 | 예 |
| 전송 중 암호화 | 예 |
| 계정 생성 | 앱에서 계정을 만들 수 없음. 앱 밖에서 만든 계정으로 로그인도 없음 |
| 데이터 삭제 요청 방법 | 아니요(스튜디오는 Google이 가진 SDK 데이터를 지울 수 없다. 처리방침 4절과 같다) |
| 데이터 유형 | 대략적인 위치, 앱 상호작용, 진단, 기기 또는 기타 ID |
| 유형마다 | 수집됨 + 공유됨 / 임시 처리 아님 / 수집은 필수 / 목적: 애널리틱스, 광고 또는 마케팅, 사기 예방·보안·규정 준수(수집과 공유 모두) |

- 근거는 Google의 [광고 SDK 데이터 공개 안내](https://developers.google.com/admob/android/privacy/play-data-disclosure)다(11/18 확인. 네 유형을 "광고, 분석, 사기 방지" 목적으로 자동 수집·공유하고 전송 중 암호화한다고 적혀 있다). 안내는 광고 ID 수집만 선택 사항이라고 하지만, 같은 칸에 앱 세트 ID도 들어가므로 "필수"로 넣었다.
- 타겟층을 18세 이상으로 고른 까닭: 13~15세 칸에는 만 13세가 들어가는데 처리방침에 아동 조항이 없고 광고 SDK가 들어 있다. 소재도 어른 쪽이다. 이 선택은 어린 이용자의 다운로드를 막지 않는다.
- 태그는 콘솔의 정해진 목록에서만 고를 수 있다. 초안의 "던지기, 싱글 플레이어, 오프라인"은 목록에 없다.

**스토어 등록정보에서 남은 것:**

- **앱 이름은 "아빠 전쟁" 그대로다.** 초안의 "아빠 전쟁: 대문을 지켜라"는 넣지 않았다. 사용자가 정한다.
- 스크린샷 순서(8장, 칸이 꽉 찼다): 떼싸움(1-4) → 쟁반 아저씨 등장 → 대장 등장 → 웅크린 대장 → 안개 낀 도전조 → 오늘의 도전장 → 1-1 → 상점. 상점 화면은 같은 날 밤 Unity에서 [새로 찍었다](dad-throw-shop-captures-2026-11-18/shop-04-shop-after-1-1.png). 11/17 캡처에는 "돌덩이 공" 카드가 있는데 지금 게임에서는 그 자리가 "피구공(다음 상품: 스포츠카)"이다.
- 아이콘과 대표 그림이 오면 올리고, "다음 → 저장"으로 마친다.

**콘텐츠 등급에서 남은 것:** 첫 화면의 "IARC 사용 약관에 동의합니다"를 사용자가 체크하면 PM이 설문 답을 넣고 요약 화면에서 멈춘다. 답은 [초안](store-listing-draft-v1.md) 2절대로다. 제출은 사용자가 한다.
