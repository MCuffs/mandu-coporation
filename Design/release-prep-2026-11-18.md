**이 빌드에서 알게 된 것:**

- **광고 SDK와 광고 ID 권한이 들어 있다.** 프로젝트에 광고 패키지가 있어서 던지기 게임이 부르지 않아도 딸려 들어간다(권한: `AD_ID`, `ACCESS_ADSERVICES_*`). 이대로 올리면 데이터 보안 신고의 "수집 없음"이 사실과 다르다. 광고 없이 올리려면 빌드에서 패키지를 빼야 한다(2절의 "광고 패키지 빼기").
- 빌드 기록의 "Android dependency resolution: False"는 광고 라이브러리 정리 도구가 템플릿 파일을 못 찾았다는 뜻이다. 빌드는 성공했지만, 광고 SDK가 반쯤 들어간 상태라 **기기에서 켜지는지는 확인되지 않았다.**

**새 앱 ID로 만든 시험 번들(같은 날 밤).** 플레이가 받는 모양(AAB)에 `com.bluemushroom.dadwar`를 넣어 디버그 서명으로 만들었다(`DadThrowAndroidBuild.TestBundle`). [빌드 기록](dad-throw-android-test-bundle-build.txt), [산출물 검사](dad-throw-android-test-bundle-artifact.json).

| 산출물 검사 | **6개 통과**: 64비트 단독, 16KB 정렬, 플레이어 데이터, 앱 ID, 타깃 API 36, bundletool의 번들 구조 검증 |

## 6. 순서 (날짜는 약속이 아니다)

1. 사용자: D-U-N-S 다시 넣기 → 가입 마치기. 결정 2번(앱 ID).
2. PM: 처리방침 고치기, 광고 패키지 빼기, 게임 안 링크. 사용자: 업로드 키 만들기.
3. PM: 서명한 AAB. 사용자: 휴대폰에 설치해 확인.
4. 사용자: 앱 만들기, 등록정보·설문 제출, 내부 테스트 시작. 그림 요청: 아이콘과 대표 그림.
5. 사람 5~8명이 해 본 기록을 보고 공개 범위를 넓힐지 정한다.
6. 앱인토스: 휴대폰 실측 → 콘솔 등록 → SDK → 등급 정보 → 심사.

## 7. 업로드 키와 스토어용 번들 (사용자가 직접)

키와 비밀번호는 사용자만 안다. PM은 만들지도, 보지도, 저장소에 적지도 않는다.

**키 만들기(한 번만).** 저장소 밖의 폴더에 만든다. PowerShell에서 실행한다(맨 앞의 `&`가 있어야 한다). 만든 파일과 비밀번호는 따로 백업한다.

```
New-Item -ItemType Directory -Force C:\Users\user\keys
& "C:\Program Files\Unity\Hub\Editor\6000.1.5f1\Editor\Data\PlaybackEngines\AndroidPlayer\OpenJDK\bin\keytool.exe" -genkeypair -v -keystore C:\Users\user\keys\bluemushroom-upload.jks -alias upload -keyalg RSA -keysize 2048 -validity 10000
```

keytool을 쓸 때(11/18 밤에 겪은 것):

- 비밀번호는 한 번만 묻는다(두 번 입력). 이 버전의 keytool은 키 비밀번호를 따로 묻지 않으므로 키 비밀번호도 같은 값이다.
- 이름, 조직, 도시는 영문으로 넣는 편이 안전하다. 도시 칸에는 도시 이름만 넣는다. 국가 코드는 숫자가 아니라 두 글자 `KR`이다.
- 마지막의 "…이(가) 맞습니까? [아니오]:"에는 **`예`** 또는 `y`를 넣는다. "네"는 알아듣지 못하고 처음 질문으로 돌아간다. 돌아갔을 때는 Enter만 누르면 앞서 넣은 값이 그대로 쓰인다.
- 끝나면 `C:\Users\user\keys\bluemushroom-upload.jks` 파일이 생긴다.

## 8. 광고 (11/18 밤, 사용자 "광고 넣어서")

**넣은 것은 보상형 광고 한 자리다.** 세로 본편 때 정한 광고 원칙(11/10)을 그대로 따랐다.

| 원칙 | 던지기 게임에서 |
| --- | --- |
| 선택해서 보는 광고만 | 판을 깬 뒤 결과 카드 아래에 "광고 보고 +N원 더 받기" 버튼. 누르지 않으면 아무 일도 없고 "다음"은 그대로 눌린다 |
| 처음에는 권하지 않는다 | 첫 세 판(1-1~1-3)에는 버튼이 없다. 4번째 판부터 나온다 |
| 진 직후에 권하지 않는다 | 패배 카드에는 없다. 오늘의 도전조에도 없다(자체 보너스가 있다) |
| 끝까지 본 사람에게만 | 광고 SDK의 "보상 획득" 신호에만 준다. 중간에 닫으면 주지 않는다. 한 번의 클리어에 한 번만 준다 |
| 남발하지 않는다 | 광고 한 번 뒤 30초 쉬고, 한 번 켠 동안 5번까지(본편과 같은 장치) |
| 배너, 강제 전면 광고 | 없다 |

- 주는 양은 그 판에서 번 돈만큼이다(두 배가 된다). 숫자는 처음 잡은 값이다.
- 광고가 준비되지 않았으면 버튼이 아예 나오지 않는다. 광고가 떠 있는 동안에는 게임의 어떤 버튼도 눌리지 않는다.
- 정지 화면에 "개인정보처리방침" 링크를 넣었다. 법이 요구하는 지역에서는 그 아래에 "광고 개인정보 선택 변경"도 나온다.
- Android에서 게임을 켜면 광고 동의 절차(UMP)와 광고 불러오기가 뒤에서 시작된다. 이 부분은 세로 본편 때 만든 코드가 그대로 돈다.
- 창 없는 검사 522개 통과(광고 6개 추가). Unity에서 가짜 광고로 [화면 5장](dad-throw-ad-captures-2026-11-18/)을 찍어 확인했다.

**아직 아닌 것:**

- **실제 광고가 뜨는 것은 한 번도 보지 않았다.** 에디터에서는 가짜 광고로만 확인했다. 휴대폰에서 시험 광고가 뜨고, 끝까지 보면 돈이 들어오고, 닫으면 안 들어오는지 봐야 한다.
- 광고 ID가 Google의 시험용이다. 실제 수익은 AdMob 계정과 광고 단위가 생긴 뒤다(사용자).
- ~~처리방침 본문이 아직 세로 본편 기준이다.~~ 같은 날 밤에 고쳐 사이트에 올렸다. 스토어 신고 초안도 광고가 있는 것으로 고쳤다([초안](store-listing-draft-v1.md) 3절). 실제 광고 ID로 바꾸면 "출시 전 시험 버전에서는 시험용 광고가 나온다"는 문장을 다시 본다.
- 광고가 사람을 더 남게 하는지, 떠나게 하는지는 모른다.

## 10. 다음: 내부 테스트 (11/18 밤에 확인)

콘솔의 "지금 테스트 시작 → 내부 테스트"에 할 일이 셋 있다. 내부 테스트는 검토 없이 최대 100명에게 바로 나간다.

- 테스트 번들(`DadWar-test.aab`)은 디버그 키라 플레이가 받지 않는다. 올릴 수 있는 것은 7절의 스토어용 번들뿐이다.
- **첫 스토어용 번들이 나왔다(11/18 22:46).** 사용자가 업로드 키를 만들고 7절의 명령으로 빌드했다. `DadWar-1.0.0-1.aab`, 30.1 MB, 버전 1.0.0(코드 1). [빌드 보고서](dad-throw-android-store-bundle-build.txt), [검사 결과](dad-throw-android-store-bundle-artifact.json). 검사: ARM64만, 16KB 페이지 정렬, 앱 ID, 타깃 API 36, bundletool 구조 검증 통과. 서명은 검증되고 디버그 키가 아니다(SHA256withRSA).
- **올리는 것은 사용자가 한다.** PM의 브라우저 도구는 한 번에 10.4 MB까지만 올릴 수 있어서 30 MB 번들을 못 올린다. 사용자가 "내부 테스트 버전 만들기" 화면의 업로드 칸에 파일을 끌어다 놓는다. 그 뒤 출시명과 출시 노트는 PM이 넣는다.
- 버전 코드 1은 이제 쓴 것으로 친다. 다음 번들은 2부터다.
- **번들이 콘솔에 올라갔다(11/18 밤, 사용자).** 콘솔이 읽은 값: 버전 1 (1.0.0), API 24 이상, 타깃 SDK 36, arm64-v8a, 설치 크기 31 MB. 출시명은 콘솔이 붙인 "1 (1.0.0)" 그대로이고, 출시 노트(ko-KR)는 PM이 넣었다: 첫 내부 테스트 버전 / 1장부터 6장까지 30판, 상점, 오늘의 도전조 / 광고는 시험용.
- **내부 테스트가 켜졌다(11/18 밤, 사용자가 "저장 및 출시").** 콘솔에 "활성 · 최신 출시 버전: 1 (1.0.0)"으로 나오고, 사용자가 만든 테스터 목록(1명)이 붙어 있다. 미리보기 화면에는 오류가 없었고 경고가 셋이었다.
- 스토어에서 검색해서는 나오지 않는다. "테스터" 탭의 "링크 복사"로 받은 참여 링크를 테스터 계정으로 로그인한 휴대폰에서 열어야 설치된다. 앱 설정과 검토가 끝날 때까지 이름은 "com.bluemushroom.dadwar (unreviewed)"로 보인다(콘솔의 안내).
- **프로덕션에는 "비공개 테스트 12명·14일" 요건이 없다.** 대시보드의 프로덕션 할 일은 국가 선택, 새 버전, 검토 전송, 게시뿐이고 잠금 사유는 "초기 설정을 먼저 완료"(스토어 등록정보) 하나다. 조직 계정이라서인 것으로 보인다.

## 11. 플레이스토어에 공개로 보이려면 (11/18 밤, 사용자 질문)

지금은 내부 테스트라 참여 링크를 받은 계정만 본다. 검색에 나오게 하려면 프로덕션 트랙으로 출시해 Google의 검토를 통과해야 한다.

| 순서 | 할 일 | 상태 | 누가 |
| --- | --- | --- | --- |
| 1 | 스토어 등록정보 마치기: 아이콘(512×512), 대표 그림(1024×500) | **마침(11/18 밤).** 납품된 그림([`store-art-v1/`](store-art-v1/))을 올리고 저장했다. 콘솔에 "검토를 위해 전송 준비 완료"로 나오고, 대시보드의 앱 설정 12개가 모두 끝나 프로덕션 할 일의 잠금이 풀렸다 | PM |
| 2 | 광고 ID 선언 | **저장(11/18 밤).** 번들을 올린 뒤 콘솔에 새로 생긴 선언이다. "예", 목적은 애널리틱스·광고 또는 마케팅·사기 예방(데이터 보안 신고와 같게) | PM |
| 3 | 프로덕션: 국가 및 지역 선택 | 열림. 아직 안 함 | 사용자 결정(한국만 먼저를 추천), PM 입력 |
| 4 | 프로덕션: 새 버전 만들기 | 열림. 아직 안 함. 내부 테스트의 번들(코드 1)을 그대로 보낼 수 있지만, 그 번들의 휴대폰 아이콘은 옛 그림(파란 바탕, 슬리퍼)이라 스토어의 새 아이콘과 다르다. 새 아이콘을 넣은 번들(코드 2)을 만들어 보내는 것을 추천한다 | PM 준비, 서명 빌드는 사용자 |

- 콘솔의 "앱 콘텐츠"는 2번을 저장한 뒤 "모두 확인했습니다"로 나온다.
- 검토에 걸리는 시간은 Google이 정한다. 새 계정의 첫 앱은 며칠 걸릴 수 있다고 알려져 있다(콘솔에서 확인한 값이 아니다).
- 12명 비공개 테스트 요건은 이 계정에 없다(10절).

**공개 전에 해 두면 좋은 것(콘솔이 막지는 않는다):**

**정해짐(11/18 밤, 사용자 "새 그림 기다리기"):** 임시본은 올리지 않는다. 그림 쪽에 넘길 [스토어 그림 요청서 v1](dad-store-art-request-v1.md)을 썼다. P0는 아이콘 512와 대표 그림 두 장이고, 이 두 장이 오면 1번이 풀린다. 요청서에 사용자가 정할 것이 셋 있다(아이콘에서 손에 든 물건, 세 줄 무늬, 로고의 부제).
