## 5. Android 시험 빌드 결과

던지기 게임을 플레이가 새 앱에 요구하는 모양으로 처음 빌드했다. [빌드 기록](dad-throw-android-test-build.txt), [산출물 검사](dad-throw-android-test-artifact.json).

| 항목 | 값 |
| --- | --- |
| 에디터, 방법 | Unity 6000.1.5f1, 창 없이, `DadThrowAndroidBuild.TestApk`(별도 사본 `C:\Users\user\DadWarWebGL`) |
| 모양 | 64비트(ARM64)만, IL2CPP, 최소 API 24, 타깃 API 36, 가로 |
| 크기 | **30.4MB**(11/11의 세로 본편 시험 빌드는 그림을 그대로 넣어 수백 MB였다) |
| 빌드 시간 | 4분 39초 |
| 산출물 검사 | **7개 통과**: 64비트 단독, 모든 네이티브 라이브러리 16KB 정렬, 플레이어 데이터, 앱 ID, 타깃 API 36, zipalign 16KB, 서명 검증 |
| 서명 | 디버그 키. 스토어에 올릴 수 없다 |
| 앱 ID | 시제품용(`com.manducorporation.dadthrow.prototype`). 다른 것과 나란히 설치된다 |
| 파일 | `C:\Users\user\DadWarWebGL\Builds\ThrowAndroid\DadThrow-arm64-test.apk` |

**이 빌드에서 알게 된 것:**

- **광고 SDK와 광고 ID 권한이 들어 있다.** 프로젝트에 광고 패키지가 있어서 던지기 게임이 부르지 않아도 딸려 들어간다(권한: `AD_ID`, `ACCESS_ADSERVICES_*`). 이대로 올리면 데이터 보안 신고의 "수집 없음"이 사실과 다르다. 광고 없이 올리려면 빌드에서 패키지를 빼야 한다(2절의 "광고 패키지 빼기").
- 빌드 기록의 "Android dependency resolution: False"는 광고 라이브러리 정리 도구가 템플릿 파일을 못 찾았다는 뜻이다. 빌드는 성공했지만, 광고 SDK가 반쯤 들어간 상태라 **기기에서 켜지는지는 확인되지 않았다.**
- **기기에 설치하거나 실행해 보지 않았다.** 연결된 기기가 없다. 사용자의 휴대폰에 이 파일을 넣어 설치하면 첫 실기기 확인이 된다.

## 6. 순서 (날짜는 약속이 아니다)

1. 사용자: D-U-N-S 다시 넣기 → 가입 마치기. 결정 2번(앱 ID).
2. PM: 처리방침 고치기, 광고 패키지 빼기, 게임 안 링크. 사용자: 업로드 키 만들기.
3. PM: 서명한 AAB. 사용자: 휴대폰에 설치해 확인.
4. 사용자: 앱 만들기, 등록정보·설문 제출, 내부 테스트 시작. 그림 요청: 아이콘과 대표 그림.
5. 사람 5~8명이 해 본 기록을 보고 공개 범위를 넓힐지 정한다.
6. 앱인토스: 휴대폰 실측 → 콘솔 등록 → SDK → 등급 정보 → 심사.
