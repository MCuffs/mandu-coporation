## 1. 런타임 로딩 준비

권장 경로는 `Assets/Resources/DadV13/`이며 아래 상대 경로를 유지해 최종 PNG 14개와 WAV 4개만 복사한다. 기존 `Art/V13Slingshot/` 원본은 보존한다. `_sources`, 미리보기, 제작 도구는 런타임에 복사하지 않는다. 좌표 데이터는 아래 값으로 코드 설정을 만들거나 JSON 로더를 마련한다.

**복사본에 원본 `.meta`를 함께 복사하지 않는다.** 동일 GUID가 중복되지 않게 Unity에서 새 GUID를 생성한다. 기존 Resources 에셋도 삭제하지 않는다. 배경은 최대 4096, 캐릭터·효과는 최대 1024, 투명 에셋 알파 사용·밉맵 끄기·Clamp를 기본으로 실제 기기 품질을 확인한다.

`Load()`에서 별도의 V13 로더를 연결한다. 현재 `DadArt.Clip(name)`은 새 WAV 이름을 자동으로 찾지 못하므로 명시적인 클립 사전 또는 전용 로더가 필요하다. 누락 파일은 개발 로그로 표시하고 기존 그림을 대체 표시해 실행을 유지한다.

## 3. 캐릭터 좌표와 자연스러운 움직임

- 지상 그림은 768×768, 발 피벗 `(384,720)`, Unity 정규화 `(0.5,0.0625)`다.
- 비행 2장은 몸 중심 `(384,384)`, Unity `(0.5,0.5)`로 회전한다. 기존 발 기준 그리기 도우미에는 비행 피벗 예외를 추가한다.
- 서 있는 기준 키 560px에 화면 키 108을 적용하면 배율은 `108/560`, 전체 캔버스 표시 크기는 약 148.1이다. 모든 자세에 같은 등방 배율을 사용한다. 웅크림·수평 비행의 가시 영역 높이를 억지로 108에 맞추지 않는다.
- 기본 비행 방향은 오른쪽이다. GUI의 아래쪽 양수 좌표에서는 `atan2(vel.y, vel.x)`와 그리기 회전 부호를 확인한다. 각도 회전과 좌우 반전을 중복해 뒤집지 않는다. 저속에서는 마지막 유효 방향을 유지한다.
- 벽 반응 그림의 왼쪽 등 접점은 원본 위쪽 기준 `(205,396)`, 반대쪽 반전 접점은 `(563,396)`이다. 캔버스 배율·피벗을 적용한 접점을 벽 앞면에 맞춘다. 몸 중심을 벽 좌표에 놓지 않는다.
- 그림 위치 보간은 렌더링에만 적용한다. 충돌 위치를 연출 때문에 이동시키지 않는다. 그림자는 지상 위치에 남기고 비행 중 작고 옅게 조절한다.
- 일반 상대 100·보스 144와 충돌 반경 축소는 변경 요청서 C01에 맞춰 함께 적용한다. 예측선과 실제 이동 모두 동일한 반경을 사용해야 한다.

## 4. 배경·화면비·충돌선

| 항목 | 이미지 좌표 또는 변환 |
| --- | --- |
| 원본 | 1080×2340 |
| 수직 벽 앞면 | 왼쪽 x=103, 오른쪽 x=976, 그림 검수 허용 오차 4px |
| 바닥 범위 | y=532~2285 |
| 9:16 크롭 | `(0,210,1080,1920)` → 논리 540×960 |
| 9:16 변환 | `x=px/2`, `y=(py-210)/2` |
| 9:19.5 전체 | 논리 540×1170, `x=px/2`, `y=py/2` |
| 사물함 세로 구간 | 568~820, 1029~1277, 1488~1735, 1935~2188 |

현재 `Arena=(64,240,412,520)`과 고정 높이 중앙 배치는 그대로 두면 새 벽과 맞지 않는다. 배경·충돌·입력·예측선이 공통 좌표 변환을 사용하도록 정리한다. C01의 세로 경기장 y=240~910을 짧은 화면 기준으로 검토하되, 바닥 범위와 HUD를 함께 고려해 최종 범위를 명시한다. 긴 화면은 복도가 확장되고 UI는 안전 영역 안에 유지되게 한다. 서로 다른 크롭 좌표를 섞지 않는다.

`Predict()`와 `TickDad()`에서 동일한 벽 앞면·반경을 사용한다. 벽 앞면에서 반경만큼 안쪽이 몸 중심 한계다. 배경 위 디버그 선으로 검수한 뒤 일반 플레이에서는 선을 숨긴다.

`AddDent()`의 기존 비스듬한 사물함 기준값은 교체한다. 새 사물함 구간을 같은 좌표 변환으로 판단하고 창문에는 찌그러짐을 붙이지 않는다. 바닥 전체를 무조건 이동 가능 영역으로 쓰지 않는다.

## 5. 이벤트·음향·UI 연결

- `SlingshotSim`에 아빠 벽 충돌의 위치·법선과 착지 이벤트를 명시적으로 전달한다. 현재 `dentSide`는 상대의 벽 충돌용이므로 이것만 보고 아빠 반응 자세를 재생하면 안 된다.
- 기존 데미지·속도·반사 규칙은 에셋 연결 때문에 임의 변경하지 않는다. 상태 이벤트와 표현 연결을 분리한다.
- 당김 루프 AudioSource는 효과음용 소스와 분리해 pitch가 다른 음에 번지지 않게 한다. 메뉴·일시정지·포커스 상실·재시작·오브젝트 해제에서도 정지시킨다.
- 터치 canceled는 발사로 처리하지 않는다. 입력 취소와 손가락 해제를 분리한다. 짧은 당김은 발사 수·튜토리얼 완료 상태를 바꾸지 않는다.
- HUD는 C02의 44px 한 줄 구성과 충돌하지 않게 배치한다. 연쇄 칩은 좌하단, 5연쇄 이상 강조는 약 0.6초를 기준으로 한다. 손 안내와 큰 연쇄 문구가 적을 가리지 않게 한다.
- 카메라 흔들림은 벽 충돌·보스 중심으로 정리한다. 보스 마무리 확대 약 0.25초는 실제 보스 처치 이벤트와 연결한다. 일반 명중마다 화면이 떨리지 않게 한다.
- C06 분노 다음 발사·C07 카드 제거·C09 장비 효과는 해당 시스템 결정과 구현을 확인한 후 연결한다. 그림이 있다는 이유로 미구현 효과를 활성화하지 않는다.

## 6. 적용 순서와 완료 기준

1. **P0:** 배경·좌표 변환·당기기 자세를 연결하고 짧은 화면과 긴 화면에서 벽·입력을 확인한다.
2. **P1:** 비행·벽 반응·착지·바람·손 안내·4종 효과음을 연결한다. 결정 전 분노·특성 아이콘은 준비 상태로 기록한다.
3. 기존 `SlingshotChecks` 검사와 B 플레이 검사를 실행한다. 좌우 벽 반사, 예측선과 실제 반사, 짧은 당김, 터치 취소, 재시작, 승패, 메뉴 복귀를 확인한다.
4. 9:16·9:19.5 화면에서 당기기·비행·양쪽 벽 반응·착지·5연쇄 화면을 남긴다. 회전 중 머리 크기·등 접점·사물함 위치·불필요한 선·상하 블록을 확인한다.
5. 당김음을 취소하거나 메뉴로 나갔을 때 소리가 남지 않는지, 벽음·착지음이 중복되지 않는지 듣는다. 에디터 검수와 Android 실기기 검수는 결과를 별도로 기록한다.
6. 경기장 변경 후 봇 검사를 다시 돌려 클리어 불가·범위 이탈을 확인한다. 자동 검사는 재미 검증을 대신하지 않는다. G1의 사람 대상 테스트는 따로 진행한다.

제작 도구의 **107개 에셋 검사 통과는 파일 검수 결과**다. Unity 임포트·게임 연결·Android 성능·사람 대상 재미 검증 완료를 뜻하지 않는다.

## 개발 완료 시 반환할 내용

- 적용 브랜치·커밋·Unity 버전과 실행한 장면.
