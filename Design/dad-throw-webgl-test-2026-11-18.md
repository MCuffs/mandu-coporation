# 가로 던지기 WebGL 시험 빌드 — 앱인토스에 올릴 수 있는지 (2026-11-18)

사용자 질문: "이거 인앱토스에 먼저 올려볼까요?" → PM 의견은 "찬성하되, 휴대폰의 토스 안에서 도는지부터 확인". 사용자가 "네, 시험 빌드"로 승인해 WebGL 빌드를 처음 만들어 보았다.

앱인토스는 Unity 게임을 WebGL로 빌드해 토스 앱 안의 웹 화면에서 돌린다. 그래서 가장 먼저 알아야 할 것은 내려받는 크기, 시작 시간, 메모리, 사람이 가득할 때의 프레임이다. **이 빌드에는 앱인토스 SDK(로그인, 리더보드, 저장소 등)가 하나도 들어 있지 않다. 휴대폰에서는 아직 돌려 보지 않았다.**

## 한 줄 결론

**돌아가기는 한다. 지금 상태로는 못 올린다.** PC 브라우저에서는 160명 판이 초당 60프레임으로 돌지만, 내려받는 크기가 96MB이고 그림이 압축 없이 407MB라 휴대폰에서는 메모리가 버티지 못할 가능성이 높다. 게임 규칙이나 그리는 방식이 아니라 **그림을 넣는 방식**이 문제이고, 고칠 수 있는 문제다.

## 어떻게 만들었나

| 항목 | 값 |
| --- | --- |
| 에디터 | Unity 6000.1.5f1, 창 없이(`-batchmode -nographics`). 이 프로젝트의 에디터(2021.3.2f1)에는 WebGL 빌드 도구가 설치돼 있지 않다 |
| 사본 | `C:\Users\user\DadWarWebGL`(커밋 `3a1082d`의 별도 작업 사본). Unity 6이 프로젝트 설정을 올려 쓰므로 원래 작업 폴더와 섞지 않았다 |
| 빌드 방법 | `DadThrowWebBuild.Build`(`Assets/DadSchoolBoss/Editor/DadThrowWebBuild.cs`). 던지기 씬 하나, 개발 빌드 아님, Gzip 압축에 로더의 자체 풀기를 켰다(아무 파일 서버에서나 열린다) |
| 빌드 시간 | 4분 36초(프로젝트를 처음 읽는 시간 포함 전체 약 7분) |
| 시험 장치 | 빌드에만 들어가는 정의 `DAD_THROW_WEBTEST`. 주소에 `?stage=15&auto=1`을 붙이면 그 판을 메모리 안의 플레이어로 열고 혼자 던지며, 판이 끝나면 다시 시작한다. 화면 아래에 프레임과 길 위의 인원이 나온다. 다른 빌드에는 들어가지 않는다 |

## 잰 것 (이 PC의 브라우저, 로컬 서버)

| 무엇 | 값 | 비고 |
| --- | --- | --- |
| 내려받는 크기 | **96MB** | 데이터 95.7MB + 코드 4.0MB. 압축한 크기다 |
| 그림(압축 풀린 크기) | **407MB** | 빌드 기록의 합계. 전부 무압축 |
| 시작까지 | 2.6초 | 같은 PC에서 받은 것이라 내려받는 시간이 없다. 통신망에서는 96MB를 받는 시간이 더해진다 |
| 프레임, 3-5(160명 판, 길 위 122명) | 60 | 1440×900 |
| 프레임, 1-5(길 위 61명), 휴대폰 가로 크기(740×360, 2배 밀도) | 60 | 화면이 가득 차고 양옆에 띠가 생긴다. 배치는 깨지지 않았다 |
| 코드가 쓰는 메모리(WASM) | 58MB | Unity가 알려 주는 값 |
| 브라우저가 알려 주는 JS 메모리 | 133MB | 데이터 파일이 올라간 메모리는 이 숫자에 다 잡히지 않는 것으로 보인다(확인 못 함) |

PC의 숫자다. 휴대폰의 처리 속도와 메모리 한도는 훨씬 낮다. **여기서 60이 나왔다고 휴대폰에서 60이 나온다는 뜻이 아니다.**

## 왜 이렇게 큰가

`Resources` 폴더에 든 것은 쓰든 안 쓰든 전부 빌드에 들어간다. 지금 그 안에 세로 본편과 옛 시제품의 그림이 같이 있다.

| 묶음 | 압축 풀린 크기 |
| --- | ---: |
| 던지기 게임이 쓰는 것(등장 컷인 62, 던지기 기본 45, 이야기 17, 화면 21, 상점 10, 인물, 글꼴 등) | 약 170MB |
| 던지기 게임이 안 쓰는 것(세로 본편 `DadV2`·`DadV11`·`DadV17` 등, 옛 `Alley` 시제품) | 약 237MB |
| 합계 | 407MB |

던지기 게임 것만 봐도 크다. 화면에서 22픽셀로 나오는 골프공 그림이 1254×1254 무압축(6MB)이고, 등장 컷인 한 장이 16MB다. 요청서의 "화면 크기의 2.6배 이상" 원칙대로 크게 받아 그대로 넣었기 때문이다.

## 앱인토스에 올리려면 고칠 것 (순서대로)

| 순서 | 일 | 기대 |
| --- | --- | --- |
| 1 | 던지기 게임이 안 쓰는 그림을 빌드에서 뺀다(던지기용 프로젝트를 따로 두거나, 안 쓰는 `Resources`를 빌드 때 치운다) | 407 → 약 170MB |
| 2 | 그림마다 최대 크기를 화면에서 쓰는 만큼으로 줄인다(공 256, 인물 768 그대로, 컷인 2048 → 1024 등) | 170 → 수십 MB |
| 3 | 휴대폰용 압축(ASTC)을 켠다 | 다시 1/4~1/8 |
| 4 | 그 빌드를 **휴대폰에서** 돌려 프레임과 메모리를 잰다 | 여기서 올릴지 말지가 정해진다 |
| 5 | 앱인토스 필수 기능 5가지(게임 로그인, 리더보드, Safe Area, 네이티브 저장소, 행동 기록)와 화면 방향 고정, Brotli 압축 | 심사 조건 |
| 6 | 연령 등급(스토어에 안 나온 게임은 게임물관리위원회 직접 신청, 심의 약 10~15일) | 출시 조건 |

1~3은 그림 설정을 바꾸는 일이라 게임 규칙을 건드리지 않는다. 다만 압축하면 선이 뭉개질 수 있어 화면을 다시 봐야 한다.

## 확인하지 못한 것

- **휴대폰에서 한 번도 돌리지 않았다.** 프레임, 메모리, 터치, 소리(브라우저는 첫 터치 뒤에만 소리를 낸다) 전부 모른다.
- 토스 앱 안에서도 돌리지 않았다. 앱인토스 콘솔 등록과 SDK가 먼저 필요하다.
- 96MB를 통신망으로 받는 시간.
- 실행 중 데이터 파일이 차지하는 메모리의 정확한 값.
- 이 빌드는 그림이 들어가기 전의 커밋(`3a1082d`)으로 만들었다. 오늘의 도전조 그림과 소리(`f8b0160`)는 들어 있지 않다.

## 다시 만드는 법

```
"C:\Program Files\Unity\Hub\Editor\6000.1.5f1\Editor\Unity.exe" -batchmode -nographics -quit -projectPath C:\Users\user\DadWarWebGL -buildTarget WebGL -executeMethod DadThrowWebBuild.Build -logFile C:\Users\user\DadWarWebGL\Logs\webgl-build.log
```

결과는 `Builds/ThrowWebGL/`에 나온다. 그 폴더를 아무 파일 서버로 열면 된다(`python -m http.server 8790 --directory …`). 사본을 최신으로 올리려면 그 폴더에서 `git checkout --detach <커밋>` 뒤 다시 빌드한다(Unity 6이 고친 설정 파일은 커밋하지 않는다).
