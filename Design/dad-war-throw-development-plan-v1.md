# 아빠 전쟁 — 가로 투척 게임 상세 개발 기획서 v1

작성: 2026-11-17 / 상태: 개발용 제안서 / 대상: Android, 가로 화면, Unity.

> 아빠는 집 앞에 서서 다가오는 어른들을 신발로 한 줄에 모으고, 골프공 한 발로 관통시킨다. 잘 던지는 것과 기다렸다 던지는 것이 모두 중요한 짧은 병맛 방어 게임이다.

## 0. 문서의 권한·상태·읽는 방법

- **확정:** 제목 아빠 전쟁, 가로 투척 방향, 정지한 아빠/오른쪽에서 접근하는 상대, 골프공·신발, 넓은 구도 v2, 불필요한 설명과 메뉴 축소.
- **현재 구현:** 별도 `Assets/DadThrowDefense.unity` 시제품과 ThrowDefense 코드. v1 그림과 손/발 앵커를 연결한 상태다. 캠페인·저장·광고와는 분리되어 있다.
- **제안:** 이 문서의 화면 수치, 수제 스테이지, 경제·저장 구조, 신규 적·물건, 제작 일정. 사용자가 모든 수치를 확정하거나 15판 전체 제작을 승인한 것으로 취급하지 않는다.
- **미확인:** 실기기 성능·안전 영역·미술 가독성·유저 재미·출시 수익성. 디자인 HTML은 Unity/Android 실행 증거가 아니다.
- 본 문서만 신규 작성한다. 기존 본편, 원본 폴더 V20, 코드, 회사 전략 결정을 변경하지 않는다. 커밋·푸시는 별도 요청이 있을 때 한다. Unity/플레이어 창은 열지 않는다.
- 문서 내 경로는 저장소 루트 기준이다. 실제 존재 경로와 **신규 예정 경로**를 구분한다. 기존 전략은 대체하지 않고 가로 시제품의 구체화에 사용한다.

## 1. 제품 목표와 하지 않을 것

### 1.1 플레이어에게 줄 경험

첫 30초 안에 ‘당겨 놓으면 날아간다’를 이해한다. 첫 3분 안에 신발과 골프공이 서로 다른 도구라는 사실을 경험한다. 실수한 뒤 적이 어디서 새었는지 알고 다음 판에서는 발사 시점을 바꾼다. 웃음은 표정·과장된 물건·타격 반응에서 나오며 긴 대사로 설명하지 않는다.

플레이 목표는 집 앞 경계를 지키며 정해진 상대를 모두 처리하는 것이다. 제작 목표는 기존 자원을 쓰는 1장 5판으로 재미를 확인하고, 통과한 부분에만 추가 원화를 투자하는 것이다. ‘상업용’이라는 표현을 기능 수나 이미지 수로 판정하지 않는다.

### 1.2 범위

| 구분 | 구성 | 완료 판단 |
|---|---|---|
| 첫 제작 권장 범위 | 타이틀·전투·정지·완료·실패, 1장 5판, 기본 물건 2개, 일반 적 1종, 최소 저장 | 처음부터 끝까지 진행·재실행 가능 |
| 검증 후 확장 | 빠른 적, 큰 적, 2장, 골프채 중 순차 선택 | 기본 도구 선택이 관찰된 후 |
| 장기 후보 | 3장, 낚싯대, 자동차, 광고 연결 | 별도 비용·재미·기기 검수 |
| 제외 | 캐릭터 장비 6부위, 뽑기, 도시 경영, 자동 전투, 일일 숙제, 다중 재화, 에너지 | 기존 시스템을 새 메뉴에 복사하지 않음 |

한 판 목표는 대략 35~100초, 첫 5판 전체 5~8분이다. 이는 실측이 아닌 튜닝 목표다. 첫 판은 짧게, 후반 판은 압박과 짧은 휴식을 교대로 둔다.

## 2. 세계관과 시작 연출

아들이 ‘상대가 아빠를 데려왔다’며 심각하게 말한다. 아빠는 말릴 생각 없이 신발부터 챙긴다. 이번 가로 버전에서는 상대가 집 앞으로 몰려오고 아빠가 물건을 던져 막는 것으로 연결한다. 기존 학교 돌진 오프닝과 장소가 충돌하므로 **전용 짧은 오프닝으로 연결할지, 시제품에서는 생략할지 미결정**이다. 기존 학교 영상에 주택가 전투를 설명 없이 붙이지 않는다.

권장 첫 버전은 검은 회사 로고 → 타이틀 → 전투다. 오프닝 제작 시 6~10초 이내의 선택 가능한 3컷만 사용한다. 아들 놀람/아빠 눈썹 움직임/신발 집어 들기 순서이며, 긴 자막·더빙·영상 재생 시스템은 첫 검증에 필요하지 않다. 재방문에는 자동 재생하지 않고 언제나 건너뛰기가 가능해야 한다.

상대는 성인 이웃 아저씨다. 학생을 반복 공격하는 화면을 새로 제작하지 않는다. 피·상처 대신 찌그러진 표정과 뒤로 밀림으로 코믹한 충돌을 표현한다.

## 3. 핵심 판단과 반복 구조

### 3.1 매 발사의 선택

| 선택 | 이득 | 비용/위험 | 읽어야 할 정보 |
|---|---|---|---|
| 바로 골프공 | 앞의 위협 즉시 제거 | 흩어진 적에게 관통 낭비 | 선두 거리, 정렬 상태 |
| 기다렸다 골프공 | 한 발에 여러 명 처리 | 경계 침입 위험 | 후속 속도와 간격 |
| 먼저 신발 | 선두를 뒤로 보내 합류·시간 확보 | 공유 재장전 동안 공을 못 던짐 | 밀칠 위치와 뒤 무리 |
| 높은 궤도 | 먼 적을 향한 다른 접근 | 앞의 적을 넘길 수 있음 | 착지와 적 높이 |
| 낮은 궤도 | 같은 줄 관통 | 착지 후 반사로 예상이 달라짐 | 바닥과 예측 점선 |

핵심 상태는 적의 위치/간격이고, 신발은 그 공간 관계를 바꾸며, 골프공은 바뀐 관계를 제거 효율로 바꾼다. 코인은 결과를 다음 판의 소폭 성장으로 넘기지만 주된 판단을 대체하지 않는다.

### 3.2 기획 구조와 근거 수준

설계 도구의 H001 ‘생성→배치’를 수제 등장표에 맞춰 무작위 선택을 삭제하여 사용한다. 발사·명중·정산 연결은 본 게임의 자체 합성이다. 반복 패턴은 학습형 루프(06): 실패 원인 정보 → 같은 배치 재도전 → 다른 도구/시점 → 달라진 결과다. 이 분류가 재미의 근거는 아니다.

`무리 접근 → 간격 관찰 → 도구 선택/조준 → 위치 변경 또는 관통 → 생존 여유/코인 → 다음 접근`

같은 판 재도전에는 배치 지식이 남고 체력·발사체·재장전은 초기화된다. 클리어 다음 판에는 진행도와 확정 코인/강화만 남는다. 확장 장에서는 속도 조합이 달라져 이전 지식을 새 상황에 적용한다.

## 4. 화면 좌표·화각·안전 영역

### 4.1 공통 좌표 계약

디자인 기준은 1280×720, 왼쪽 위 (0,0), x는 오른쪽, y는 아래다. 아래 Rect는 `(x,y,w,h)`이다. 물리 모델과 화면 변환을 분리하고, 손가락 좌표는 안전 영역/레터박스 변환을 역적용한다. 기기 픽셀을 모델 좌표로 직접 사용하지 않는다.

현재 코드 `DadThrowLayout.cs`는 아빠 발 `(130,575)`, 키 190, 바닥 570, v1 배경을 쓴다. `DadThrowModel.cs`의 경계 x=215, 발사점 `(243,440)`은 v1 앵커와 대응한다. **이 값은 확인한 현재 값이며 v2 배경에 자동으로 맞는 값이 아니다.**

권장 첫 v2 전투도 아빠 높이 170~190, 적 100~115 범위에서 비교한다. **(2026-11-17 사용자 결정: Unity 실행 화면을 보고 인물 크기를 맞췄다. 아빠 키 115, 상대 102~112. 170~190은 상대의 1.7배로 너무 컸다.)** 타이틀 그림 속 작아진 인물 비율을 그대로 충돌 크기에 적용하지 않는다. 실제 바닥·손·대문 위치를 측정한 후 하나의 Layout 데이터에서 모델/표시가 같이 읽게 한다.

### 4.2 화면비 정책

- 16:9에서는 1280×720 전체를 기준으로 한다.
- Galaxy S21 Ultra 등 더 긴 가로 화면에서는 전투 논리 영역을 가운데 유지하고 바깥은 저채도 배경 연장 또는 레터박스를 사용한다. 초반에는 적이 더 일찍 보이는 식으로 난이도를 바꾸지 않는다.
- 안전 영역은 Unity `Screen.safeArea`를 읽어 계산한다. 노치 방향·내비게이션 방향 양쪽을 확인한다. 특정 기기의 고정 픽셀 여백을 모든 기기에 쓰지 않는다.
- 세로로 잡으면 가로 전환 안내를 단순하게 표시한다. 전환 중 입력을 취소하고 전투 시간을 멈춘다.
- 장식 배경과 UI 변환을 분리한다. `ScaleToFill`로 인물 얼굴이나 공을 가로로 늘리지 않는다.

| 요소 | 기준 Rect/앵커 | 표시/행동 | 비고 |

| 집 내구도 | (230,20,230,48) | 집 아이콘+5칸 | 적 머리 HP바 남발 금지 |

상단 HUD는 얇게, 가운데 전투면은 비워둔다. 전투 중 코인·업그레이드·대사·전투력·누적 피해량은 숨긴다. 버튼 그림이 작아져도 터치 영역은 축소하지 않는다. UI 공간과 투사체 유효 공간은 겹치지 않게 구분한다.

## 5. 전체 화면 흐름과 상태 전이

`Boot → Title → (첫 회 선택적 Intro) → StageLoading → Playing ↔ Paused → Clear 또는 Defeat`

`Clear → Upgrade(같은 카드 내부) → NextStage / Title`

`Defeat → Retry(같은 판) / Title`

| 상태 | 진입 작업 | 허용 입력 | 나가는 조건/정리 |
|---|---|---|---|
| Boot | 저장 검증, 최소 그림/폰트 로드 | 건너뛰기 가능 여부 별도 | 준비 완료 후 타이틀, 실패 시 명시 오류 |
| Title | 진행에 따라 시작/계속 문구 | 시작·소리 | 중복 클릭 잠금 후 로드 |
| StageLoading | 데이터 검증, HP5, 적/탄 초기화 | 없음 | 준비 후 Playing, 잘못된 데이터는 개발 오류 |
| Playing | 스폰·이동·재장전 갱신 | 선택·드래그·정지 | HP0이면 Defeat 우선, 잔여0이면 Clear |
| Paused | 시뮬레이션/재장전 정지, 조준 취소 | 계속·소리·나가기 | 계속해도 손가락 놓기로 자동 발사 금지 |
| Clear | 탄 제거, 보상 거래 1회, 저장 | 강화·다음·타이틀 | 동시 구매/다음 입력 직렬 처리 |
| Defeat | 스폰 중단, 탄 제거, 실패 반응 | 재도전·타이틀 | 미확정 전투 코인 폐기 |

앱 백그라운드·포커스 상실은 Playing을 Paused로 보낸다. 결과 상태는 자동으로 다시 전투가 되지 않는다. Android 뒤로가기는 전투에서 정지, 정지/결과에서 타이틀 복귀 선택으로 처리한다. 소리 설정은 즉시 저장한다.

## 6. 비전투 화면 상세

### 6.1 회사 로고

검은 배경 위 `Mandu Corporation`을 실제 텍스트로 중앙 표시한다. **(2026-11-17 사용자 결정: 로고 문구는 스튜디오 이름 `Bluemushroom studio`로 한다. 시제품 코드에 반영함.)** 초기안 총 1.2초(등장 .2/유지 .8/퇴장 .2), 로딩이 길면 검은 화면을 고정하지 않고 작은 로딩 표시를 제공한다. 회사 로고 그림은 현재 전용 신규 제작 불필요다. 기존 게임 배경을 로고 뒤에 섞지 않는다.

### 6.2 타이틀

배경 `DadThrowScreensV2/title_wide`를 사용한다. 키아트의 아빠와 적은 이미 그림에 들어 있으므로 별도 캐릭터를 위에 중복 배치하지 않는다. `아빠 전쟁`은 BlackHanSans 실시간 텍스트, 테두리 있는 짙은 먹색/노랑 조합이다.

초기 Rect: 제목 (290,75,700,165), 시작 (490,600,300,72), 소리 (1180,24,64,64). 부제·스튜디오 설명·광고 보상 안내는 넣지 않는다. 이어할 판이 있으면 `계속하기`, 없으면 `게임 시작`. 버튼을 누르면 즉시 눌림 상태를 보이고 중복 진입을 막는다.

### 6.3 완료

`street_wide` 배경 + `DadThrowScreensV1/dad_clear`를 왼쪽, 결과 카드 (650,218,460,330)를 오른쪽에 둔다. 캐릭터 그림의 투명 여백을 포함한 전체 Rect와 실제 몸통 높이를 구분한다. HTML v2의 이미지 박스는 폭410 기준이며 게임 배치는 alpha bounds/발 앵커를 다시 사용한다.

카드 내용은 `막았다!`, 코인 변화 한 줄, 강화 한 개, 다음 버튼이다. 누적 코인과 지급 코인을 별도 라벨 5개로 늘리지 않는다. 강화 불가 시 부족한 값만 짧게 표시한다. 구매 후 같은 카드가 갱신되며 새 팝업을 띄우지 않는다. 1-5 완료에는 다음 장 미제작 시 `여기까지 막았다!`와 다시 하기/타이틀을 보여준다. 존재하지 않는 2장으로 이동하지 않는다.

### 6.4 실패

`dad_retry`를 왼쪽에 사용한다. 문구는 `다시 해볼까?`, 큰 재도전 버튼, 작은 타이틀 버튼이다. 실패 이유는 실제 사건에 맞춰 `집 앞까지 들어왔어요` 한 줄만 허용한다. 공격력 부족으로 단정하거나 구매를 강요하지 않는다. 실패 직후 광고·강화 판매를 덮어씌우지 않는다.

### 6.5 정지

전투 화면을 멈춘 채 검정 55~65% 오버레이와 중앙 카드 (445,145,390,430)를 둔다. 계속/소리 켜기·끄기/타이틀 세 가지다. 카드를 여는 동안 조준선을 지우고 잡고 있던 발사는 취소한다. 나가기 선택 시 현재 판만 초기화되고 저장된 진행/확정 코인은 유지된다.

## 7. 입력과 조준의 상세 규칙

1. Playing이며 재장전 완료일 때만 새 조준을 시작한다. UI 위 터치는 전투로 전달하지 않는다.
2. 첫 손가락 ID를 소유자로 저장한다. 다른 손가락은 선택/발사를 바꾸지 못한다.
3. 누른 점에서 뒤로 당긴 벡터를 전방 속도로 바꾼다. 최소 드래그18, 최대150 기준 좌표. 화면 이동 비율이 달라도 기준 단위로 역변환한다.
4. 예측선은 아빠 발사 손에서 시작하고 무기 선택과 같은 물리를 사용한다. 처음부터 화면 끝까지 밝은 선을 깔지 말고 다음 착지까지 제한된 점으로 표시한다.
5. 놓으면 충분한 드래그일 때 한 번 발사한다. 짧은 탭·포커스 상실·정지·회전은 취소이며 재장전을 소모하지 않는다.
6. 재장전 중에는 버튼 테두리/채움으로 상태만 보이고 매번 `아직 못 던짐` 텍스트를 띄우지 않는다. 완료 후 손을 다시 내려 조준한다. 자동 연사는 첫 범위에서 없다.
7. 조준 중 다른 물건 버튼을 누르면 기존 조준을 취소하고 선택만 바꾼다. 공이 날아가는 중 선택 변경은 이미 발사된 공에 영향을 주지 않는다.

현재 모델의 전방 최소속도180은 거꾸로 던짐을 방지하지만 수직 당김도 앞으로 날아가게 한다. 튜토리얼에서 방향 오해를 관찰하면 부채꼴 방향 제한/시각 피드백을 먼저 비교한다. 속도 규칙을 조용히 바꾸지 않는다.

### 8.2 명중·밀치기·정산

- 스텝당 최대 1/120초의 분할 이동과 연속 구간 판정을 유지한다. 저FPS에서 공이 적을 건너뛰지 않아야 한다.
- 현재 판정은 적 중심 `(x,535)`, 적 반경25와 탄 반경의 합을 사용한다. 그림의 얼굴이나 발 전체와 동일한 판정이 아니다. 디버그 표시에서 불일치를 먼저 확인한다.
- 한 공이 같은 enemyId를 두 번 때리지 않는다. 여러 적이 동시에 교차하면 **비행 선분상의 가까운 충돌부터** 처리하는 것으로 개선 제안한다. 현재 리스트 역순 순회와 다르므로 관통 한도 테스트가 필요하다.
- 신발은 첫 직접 충돌 상대에게 피해1, 주변에는 밀치기/감속만 준다. 죽은 직접 대상도 주변 밀치기의 기준점은 유지한다. 주변 전부에게 피해를 주는 것으로 오해시키는 폭발 이펙트를 금지한다.
- 반복 신발 감속은 남은 시간을 최대2.5초로 갱신하며 속도배율을 곱해서 영구 정지시키지 않는다. 큰 적 저항 도입 시 밀치기만 줄이고 피드백은 남긴다.
- 현재 처리에서는 적 경계 침입이 탄 충돌보다 먼저다. 초기 제작도 동일하게 유지하되 ‘선분상 먼저 맞았는데 놓침’이 보이면 경계/명중 사건을 시간순으로 통합해 검증한다.
- 경계 통과한 적은 즉시 제거하고 HP1 감소, 한 적은 한 번만 누수 처리한다. HP0이면 클리어보다 실패 우선이다.
- 마지막 상대가 제거되거나 누수된 뒤 미등장 수0이고 HP>0이면 클리어다. 남은 공이 결과 화면 뒤에서 움직이지 않는다.

## 9. 캐릭터·애니메이션·타격 연출

### 9.1 아빠

Ready → 드래그 중 Windup → 놓는 즉시 Release(.22초 현재) → Ready. 발 피벗은 모든 포즈에서 같아야 한다. 팔 크기 변화나 몸 비율 차이를 카메라 흔들기로 숨기지 않는다. 현재 세 그림은 키포즈이며 연속 프레임 애니메이션으로 검증되지 않았다.

우선은 키포즈 전환+미세 몸 이동으로 검증한다. 보완이 필요하면 손을 앞으로 내미는 연결 포즈1장과 회복 포즈1장을 추가 제작한다. 발 이동 허용 오차 기준 좌표2px 이내, 포즈별 머리 크기 차이 대략5% 이내를 작업 기준으로 제안한다. 출현 공은 release 손에서 생성하며 windup 손에는 선택한 물건1개만 표시한다.

### 9.2 상대

일반 적은 기존 gum walk를 임시 사용한다. 코드가 이미 왼쪽을 보는 리소스를 추가 반전하고 있는지 실물 검수가 필요하다. `DadArt` 주석은 상대 기본 방향이 왼쪽이라고 설명하지만 시제품은 flip=true를 전달한다. **방향 확인 없이 이를 정상으로 승인하지 않는다.**

걷기는 2프레임 시제품부터 시작하되 발 접지·미끄러짐을 보고 4프레임으로 보완한다. 피격은 .10~.16초 흰 플래시/짧은 뒤로 움찔. 처치는 .2~.35초 뒤로 빠지며 페이드, 처치 잔상 동시 최대3개. 사람 몸을 화면 밖으로 회전시키거나 거대한 피해 숫자로 덮지 않는다.

제목 약94, 결과46, 버튼26~32, HUD24~28 기준을 초기안으로 쓴다. 길이가 늘면 글자를 무제한 축소하지 않고 문구를 줄인다. 핵심 글자에 두꺼운 검정 외곽선과 여러 그림자를 겹치지 않는다. 본문은 적당한 굵기와 단색 패널로 대비를 확보한다.

글자는 PNG에 굽지 않는다. 버튼/카드는 Unity UI 이미지·9슬라이스 또는 벡터적 단순 도형으로 만든다. 노란 주요 버튼, 크림색 종이, 먹색 테두리, 절제된 붉은 경고를 일관되게 쓴다. 일반 플랫폼 대시보드처럼 둥근 카드·작은 라벨·그라데이션을 쌓지 않는다.

### 13.1 데이터 작성 규칙

현재 25px/s와 자동스폰은 거리900px 이동에 약36초가 필요하므로 배치표 없이 복사하면 쉬운 대기 게임이 될 수 있다. 아래는 **별도 제작안**이며 현재 난이도 값이 아니다. 일반 속도 초기48px/s, HP1, 관통5, 공 피해1, 체력5로 비교한다. 사람 테스트 결과 속도35~65 범위에서 조정한다.

등장표는 그룹 시작시각/인원/개체 간격/처음 위치를 가진다. x>1280은 화면 밖이며 조용한 무적 대기실이 아니라 같은 속도로 진입한다. 첫 판에만 적이 이미 보이는 배치를 쓴다. 그룹 간격은 초 기준, 거리 간격은 px 기준으로 저장해 단위를 혼동하지 않는다.

화면 밖 적을 시작 때 대량 생성하면 남은 수/활성 수가 헷갈릴 수 있으므로 StageRunner는 표시 적과 예정 적을 분리한다. 스폰 시점에도 x가 화면 밖이면 미등장 처리 정의를 일관되게 유지한다. 남은 수는 예정+살아있는 수이고 클리어는 둘 다0일 때다.

초반은 한 번에 도구 하나의 차이만 학습한다. 압박을 늘릴 때 인원·속도·HP·진입간격을 동시에 바꾸지 않는다. 1장에는 HP2 적, 방패, 점프, 투사체, 암전이 없다. 강화 없이 통과 가능한 기준선을 확보한 뒤 성장 보상을 붙인다. 똑같은 판을 실패했다고 내부 속도를 몰래 줄이지 않는다.

## 15. 보상·강화·경제

### 15.1 현재와 제안 차이

현재 모델은 처치 즉시2코인, 클리어10+Wave×2, 강화비30+25×Level, 최대5단계이며 재시작 시 초기화된다. 아래는 저장을 위한 새 거래 규칙 제안이다. 현재 동작인 것처럼 UI 숫자를 연결하지 않는다.

결과 진입마다 새 보상을 만들지 않는다. runId와 rewardCommitted를 저장하여 중복 완료/재개를 막는다. 구매는 잔액 확인→차감→강화 반영→한 번 저장으로 처리한다. 구매 애니메이션 도중 다음 클릭도 직렬화한다. 저장 실패 시 확정 안내를 띄우지 않고 재시도 가능한 상태를 둔다.

## 16. 저장·재개·에러 처리

제안 저장 필드: schemaVersion, lastUnlockedStage, selectedStage, coins, upgradeLevel, selectedWeapon, soundEnabled, introSeen, lastCommittedRunId. 로컬 저장이며 서버 동기화/다기기 복구는 초기 범위 밖이다.

- 잠금 해제는 클리어 확정 시만 증가한다. 실패로 감소하지 않는다.
- 전투 중 앱 종료 시 타이틀에서 같은 판을 처음부터 재개한다. 날아가는 공/적 중간 상태는 저장하지 않는다.
- 쓰기는 임시 파일→검증→교체+백업 방식 제안. 사용 기술은 Unity 버전/플랫폼에 맞게 구현자가 검증한다.
- 비정상 코인/존재하지 않는 판/이전 schema는 안전한 값으로 보정하고 개발 로그에 이유를 남긴다. 모든 오류를 조용히 신규 게임으로 덮어쓰지 않는다.
- 저장 파손 시 백업 복원, 둘 다 실패하면 초기화 선택 안내. 전투가 검은 화면에서 멈추면 안 된다.
- 리소스 누락 시 개발 빌드에서 누락 키를 표시하고 체크를 실패시킨다. 출시 빌드가 하얀 사각형 캐릭터로 계속 진행하도록 두지 않는다.

## 18. 아트 임포트·빌드·성능 기준

### 18.1 이미지 파이프라인

비픽셀 그림이므로 Point/정수배 확대를 일괄 강제하지 않는다. 현 자산의 bilinear/clamp/no mipmap을 출발점으로 투명 테두리·압축 손상을 기기에서 본다. 투명 캐릭터는 alpha 유지, 배경은 불필요한 alpha 제거 후보다. 원본을 덮어쓰지 않고 런타임 내보내기와 분리한다.

배경1672×941 RGBA32는 약6MiB/장, 1254² RGBA32는 약6MiB/장이다(밉맵·엔진 오버헤드 제외). 여러 메뉴의 그림을 모두 상주시켜도 공짜가 아니다. 결과 포즈는 필요한 화면에서만 로드/캐시 해제 정책을 정한다. Resources 전체 LoadAll의 범위를 줄이고 현재 전투에 필요한 키만 읽는 방향이다.

아틀라스 사용 시 패딩/외곽 확장을 적용하고 투명 경계의 검정/흰 테두리와 타일 이음선을 검수한다. ASTC 등 플랫폼 압축은 실제 Android 환경에서 비교 후 결정하며 이번 문서에서 품질을 확인했다고 하지 않는다.

### 18.2 기술 목표와 실기기 표

- S21 Ultra: 목표 안정60fps, 장기 부하/발열과 30fps 저하 때도 동일 판정. 목표일 뿐 측정 전이다.
- 초기 동시 적24·탄6·충돌효과12·퇴장잔상3 상한 시나리오로 측정한다. 적80은 스트레스용이지 콘텐츠 목표가 아니다.
- 평균뿐 아니라 긴 프레임/GC 할당을 본다. 전투 반복 루프의 매 프레임 새 리스트/문자열 생성은 줄인다.
- 저사양 Android는 확보 기종 미정. 해상도·칩셋·메모리·OS를 기록한 실제 단말에서 추가 확인한다.
- 첫 로딩/스테이지 재진입/10회 재도전 메모리 증가를 비교한다. 측정값 없이 최적화 완료라고 하지 않는다.

현재 Mac Unity 환경과 기존 Android APK의 제작 환경이 다르므로 빌드 도구/Android 모듈 호환성부터 확인한다. 새 APK에는 버전·git commit+dirty 표시·씬·개발 시각을 기록하여 Unity에서 본 것과 설치본이 다른 문제를 추적한다. 기존 `DadWar-v0.3.1-arm64-test.apk`를 새 가로 버전의 검증 결과로 쓰지 않는다.
