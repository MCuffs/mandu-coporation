# R-01 저장 복구 수정

2026-11-09. 출시 검수에서 재현한 저장 복구 결함을 수정했다. R-02~R-04와 실기기·사람 검증은 별도이며 전체 출시 판정은 여전히 NO-GO다.

- 저장 후보를 원본→백업→tmp 순서로 읽되, 필수 version·coins·진행 정보가 누락된 객체나 허용 범위 밖 수치는 건너뛴다. `FromJsonOverwrite`에 필수 값의 sentinel을 넣어 `{}`가 정상 새 게임처럼 보이지 않게 했다.
- v1/v2와 누락된 선택 배열은 지원한다. v1 장비 이전과 과거 상한 초과 구매 레벨을 보존한다. 더 최신 버전의 파일이 있으면 구버전 백업으로 덮지 않고 읽기 전용 실패 상태로 둔다.
- 정상 후보를 찾지 못했고 기존 파일이 하나라도 있으면 `RecoveryFailed`를 켠다. 파일이 전혀 없는 새 설치와 구분한다. 이 상태의 `Persist()`는 쓰기 전에 거절하므로 원본·백업·tmp를 덮지 않는다.
- 메인 시작/Update/OnGUI가 복구 실패 상태를 처리한다. 게임 진행 대신 ‘저장 기록을 읽지 못했어요’ 화면과 다시 불러오기·앱 종료를 제공한다. 사용자 파일을 자동 삭제하거나 새 게임으로 덮는 버튼은 없다.
- 정상 백업 복구 뒤 재저장할 때 손상된 원본이 정상 백업을 덮지 않는다. 메모리에서 비정상 수치가 생겨도 파일 쓰기 전 검사한다.

## 검증

설치 Unity2021.3.2f1에서 창 없는 배치 검사를 실행했다. 신규 저장 검사26개 통과, 네이티브 감사8개 그룹 모두 통과. 이전 감사의 `{}` 원본/코인123 백업 재현도 이제123으로 복구됐다. 기존 관리 코드161개도 통과했다.

검사에는 빈 객체·잘못된 루트·중첩된 가짜 필드·필수 필드 누락·음수·잘못된 진행·잘못된 배열, tmp 복구, 복구 후 재저장과 백업 보존, 전체 실패 시3개 파일의 원문 보존, 수동 복구 후 재시도, v1/v2 호환, 미래 버전 보호와 NaN 쓰기 거절이 포함된다. 모두 임시 파일을 사용했으며 실제 사용자 진행을 수정하지 않았다.

증거: `dad-save-recovery-checks.txt`, `dad-save-fix-native-audit.txt`, `dad-save-fix-economy-checks.txt`. 복구 실패 UI는 컴파일·분기 검수만 했고 실제 화면·손가락·Android의 강제 종료 중 파일 교체는 미검증이다.

재현: `Unity -batchmode -nographics -projectPath <검수 사본> -executeMethod DadReleaseAudit.Batch -logFile <로그>`. 검사 결과는 `dad-save-fix-native-audit.txt`에 쓴다. 기존 경제/에셋 보고서와 importer 메타도 갱신될 수 있으므로 검수 사본에서 실행한다.
