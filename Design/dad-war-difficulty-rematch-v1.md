# 난이도·단톡방 재대결 v1

2026-11-06. 기준은 메인 슬링샷 게임. 이전 성장·재도전 보완 위에 구현했다. 새 원화를 생성하지 않고 기존 UI·캐릭터·효과음을 사용했다. 아래 수치는 첫 조정값이며 사람의 반복 플레이/리텐션 효과는 아직 검증하지 않았다.

## 문제와 측정

기존 비행 중 무적을 유지한 채 거의 즉시 다시 쏠 수 있어, 빠르게 부정확하게 쏘는 봇도 1-20을 12/12회 이겼다. 적 체력이나 공격력만 올리면 이 전략은 남고 신중하게 조준하는 사람만 더 어려워질 수 있다.

따라서 핵심 조정은 **발사 효율과 연쇄의 가치**다. 실패의 원인이 남은 발사 수/상대 수로 보이고, 다음 시도에서 각도·대상·장비를 바꿀 수 있게 한다.

## 일반 진행

- 1-1~1-9: 발사 한도 없이 조작과 역할 교육. 1-5/1-8은 역할 소개 뒤 압박을 소폭 높였다. 1-6은 쉬운 몸풀기 판 유지.
- 1-10부터: 별 목표보다 8발 여유 있는 한도. 실패 조건과 별 3개 조건을 분리한다. 예: 별 목표 15발, 클리어 한도 23발.
- 홈 출발 카드에 별 목표와 클리어 한도, 전투 HUD에 남은 발사를 표시한다.
- 1-11 이후 생성 판은 웨이브 간격을 줄이고 층·판에 따른 속도 상승폭을 늘렸다. 새 적 체력 배수는 추가하지 않았다.
- 비행이 끝났을 때 3연쇄 미만이면 0.48초, 3연쇄 이상이면 0.16초 회복. 비행 중 무적은 유지하되 무한에 가까운 재발사를 줄인다.
- 회복 중 놓은 정상 당김 입력은 다음 발사 1개로 예약해 유실을 줄인다. 새 당김·취소·포커스 상실·판 종료/교체 때 예약을 지운다.
- 한도를 다 써도 마지막 비행, 날아가는 상대, 되받아친 공의 연쇄가 끝날 때까지 기다린다. 마지막 발로 전원 제압하면 승리. 아니면 정착 후 `발사 소진 · N명 남음`으로 패배한다.
- 일반판 연속 3패부터 기존 체력 응원과 함께 발사 +1, 이후 최대 +5까지 보정. 재대결 한도는 바꾸지 않는다.

## 단톡방 재대결 3단계

깬 판마다 해금되는 선택형 도전. 일반 진행을 막지 않는다.

- 진입: 홈 `지난 판 · 별 도전` → 각 판의 `재대결 N단계`. 정상 승리 결과에서도 진입 가능.
- 1단계부터 순서대로 해금. 완료한 단계는 반복 가능.
- 기존 역할 소개 이전의 적은 추가하지 않는다. 초반 판은 접근형만, 의자·쟁반·피구는 소개된 판부터 혼합한다.
- 단계당 속도 +12% 배율, 좌우 다른 위치에 지원군 추가. 1/2/3단계 지원군은 각각 2/3/4명.
- 발사 한도는 별 목표 +4/+3/+2. 체력 배수로 버티게 하지 않고 발사 계획과 역할 우선순위를 요구한다.
- 최초 승리 보상: 코인 `해당 판 기본 코인 × (1 + 단계 × 0.5)`, 도시락 1/2/3개.
- 완료한 단계 보상은 저장 후에도 다시 지급되지 않는다. 실패/완료 단계 재승리는 코인·도시락을 지급하지 않는다. 입장료/광고 부활/에너지 제한은 추가하지 않았다.
- 일반 스테이지 해금, 별, 최소 발사 기록, 선택 목적지는 재대결 결과로 덮지 않는다. 재대결 완료 단계만 별도 저장한다.
- 결과에서는 실패 원인과 같은 단계 재도전, 성공 시 다음 단계 진입을 보여준다.

지원군이 연쇄의 매개가 되므로 단계가 높을수록 모든 전략의 승률이 반드시 감소한다고 단정하지 않는다. 수치 증가뿐 아니라 조합이 다른 장면을 만드는지 실제 플레이로 확인해야 한다.

## 일반판 별 3개 최초 달성 보상

각 판이 처음 별 3개가 되면 기본 코인의 50%와 도시락 1개를 추가 지급한다. 결과에 추가 보상 포함 문구를 표시한다. 별 3개가 이미 저장된 판에는 소급/중복 지급하지 않는다. 최초 클리어 때 3개를 달성해도 보상은 한 번이다.

## 저장과 에디터 안정성

- 저장에 `rematchRanks` 추가. 기존 v2 파일에 없으면 빈 배열로 처리하며 기존 진행·재화·장비는 유지한다.
- 잠긴 판/단계 건너뛰기는 진입과 보상 처리 모두에서 검사한다.
- 플레이 중 스크립트 재컴파일로 진행 객체가 사라졌을 때 저장 데이터를 다시 연결하도록 고쳤다. 홈 배경에서 null 참조가 반복되던 현상을 검수 중 발견해 수정했다.
- 화면 감사는 별도 임시 저장을 사용하며 PlayerPrefs와 실제 진행 객체를 복원한다. 강제로 만든 승패 캡처는 UI 검수 자료이고 사람 플레이 결과가 아니다.

## 봇 결과와 한계

조건: 업그레이드/도시락 패시브 없음, 시작 특수 발사 벽 피해 +1, 고정 12시드. 상대를 직접 노리는 단순 정책이며 벽 우회 전략을 계획하지 않는다. 빠른 반복은 오차 60°·조준 0.05~0.1초, 초보는 20°·1.5~2.5초, 정밀은 5°·0.6~1초. 입력 속도와 정확도가 함께 다르므로 정확도 하나의 효과를 분리한 실험이 아니다.

| 조건 | 빠른 반복 | 초보 | 정밀 |
|---|---:|---:|---:|
| 변경 전 일반 1-20 | 12/12 | 9/12 | 12/12 |
| 변경 후 일반 1-20 | 2/12 | 8/12 | 11/12 |
| 재대결 1-10, 3단계 | 0/12 | 10/12 | 10/12 |
| 재대결 1-20, 3단계 | 0/12 | 6/12 | 9/12 |

이는 무조건 빨리 반복하는 정책의 우위를 줄였다는 국소 근거다. 실제 난이도, 공정함, 재미, 중독성이나 D1 유지율을 검증한 결과가 아니다. 성장한 저장에서는 쉬워질 수 있으며 그 체감도 사람 테스트로 판단한다.

재현: Unity 메뉴 `Dad School Boss/Run Difficulty Policy Bot`, 또는 `Library/DadPrototypeCommand.txt`에 `difficultybot`. 전/후 및 재대결 보고서는 `dad-difficulty-bot-before.txt`, `dad-difficulty-bot-after.txt`, `dad-rematch-bot.txt`.

## 검수와 다음 판단

- 전체 런타임/에디터 코드 컴파일.
- 독립 실행 회귀: 기존 성장·슬링샷 + 새 난이도/보상 검사. `dad-difficulty-headless-checks.txt`.
- Unity 실검사: `Dad School Boss/Run Difficulty Checks`. 한도 마지막 발 처리, 반환 공 대기, 단계별 해금, 보상 중복 차단, 기존 JSON 호환과 재로드 등을 확인. `dad-difficulty-checks.txt`.
- Play Mode 연결 검사와 경제/에셋 검사도 실행한다. 결과는 각 검사 보고서 기준이다.
- `difficultyui:<폴더>`는 판 목록/재대결 시작/조준/승리/실패 5장 감사 캡처. 임시 상태로 촬영 후 실제 진행을 복원한다.
- Android 실기기 및 사람 테스트는 아직 하지 않았다.

다음 사람 관찰은 현재 저장과 새 저장을 구분한다. 첫 실패 후 각도/대상/당김 세기를 바꾸는지, 한도가 처음부터 보이는지, 실패가 억울함인지 도전 의욕인지 확인한다. 쉬우면 숫자부터 올리기보다 직선 연타가 통하는 배치와 분노 발사 빈도를 살핀다. 어렵다면 한도·지원군 타이밍·착지 회복 중 한 요소씩 바꾼다.

## 최종 실행 결과 (11/6)

- 독립 Mono 회귀 검사 76개 통과.
- Unity 난이도·저장 검사 59개, Play Mode 연결 검사 50개, 경제·에셋 검사 보고서 73개 통과(보고서 합계 182개).
- 실제 Unity에서 판 목록/시작/조준/성공/실패 5개 화면을 확인했다. 캡처는 [UI 감사 폴더](dad-difficulty-ui-v1/)에 있다. 승패는 UI 확인을 위해 강제로 만든 상태이며 밸런스 증거로 쓰지 않는다.
- 감사 완료 후 실제 진행 객체와 PlayerPrefs를 복원했다. 플레이 중 재컴파일 뒤 홈도 정상 표시되는 것을 확인했다.
- 현재 수치의 사람 플레이 검증과 Android 터치 검증은 남아 있다.
