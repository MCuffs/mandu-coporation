# UI 전반 검토 v8 — 가독성과 홈 화면 구조

검토일: 2026-11-04. 기준: 사용자가 제공한 홈 스크린샷과 현재 Unity 소스. 홈은 이미지와 코드를 함께 확인했고, 전투·장비·선택·결과·개봉 화면은 코드 기준 검토다. 이번 검토에서 새 Android 실기기 실행이나 글꼴 렌더링 비교 실험은 하지 않았다. 게임 코드와 에셋은 변경하지 않았다.

## 판단

현재 화면은 캐릭터보다 임시 UI의 인상이 강하다. 큰 사각형, 같은 굵기의 글자, 과도한 테두리, 정보의 긴 문장 나열이 구식 인상을 만든다. 캐릭터의 우스꽝스러운 인상과 거친 외곽선은 유지할 수 있다. UI까지 거칠게 만들어야 병맛이 전달되는 것은 아니다.

추가 이미지 생성보다 **문자 선명도 확인 → 홈 정보 배치 → 공통 컴포넌트 정리** 순서가 우선이다.

## 1. 글자: 확인된 문제와 미확인 원인

| 항목 | 확인 내용 | 조치 |
|---|---|---|
| 제목 폰트 남용 | `Button()`이 모든 문구를 `display=true`로 그린다. Black Han Sans가 작은 보상 안내·장비 설명·긴 선택지에도 사용된다. | 제목과 짧은 행동명만 제목체. 설명은 Gothic A1 Regular/Bold로 분리한다. |
| 작은 글씨 | 홈 보상 17, 체력 14, 조작 안내 16, 장비 비교 18 등. 수치는 540×960 논리 좌표 기준이며 Android dp가 아니다. | 실제 기기에서 먼저 읽기 기준을 정하고, 작은 정보는 확대하거나 생략한다. |
| 계층 부족 | 기능명·효과·가격이 같은 버튼 텍스트 안에 같은 폰트로 합쳐진다. | 이름·설명·수치를 별도 텍스트 영역으로 분리한다. |
| 전체 스케일 | `ViewScale`과 `GUI.matrix`로 540×960 전체를 확대·축소한다. 소수 배율도 가능하다. | 원본 해상도 캡처와 Game View 표시 배율을 비교하여 확대 과정의 영향을 확인한다. |
| 폰트 파일 | Gothic A1 Bold와 Black Han Sans를 실제 로드한다. 메타의 fontSize 16만으로 전체 문자가 16px 비트맵이라고 단정할 수 없다. | 임포터 상태와 런타임 표시를 함께 확인한다. 이미지 생성에 글자가 구워져서 생긴 문제로 취급하지 않는다. |

스크린샷에서는 제목·본문 모두 가장자리가 거칠다. 하지만 현재 근거만으로 폰트 자체, Unity 렌더링, Game View 확대, 캡처 재샘플링 중 어느 것이 주원인인지 확정할 수 없다.

검증 절차:

1. 같은 화면을 원본 540×960, 1080×1920에서 캡처하고 파일을 100% 배율로 확인한다.
2. Game View 확대 배율과 캡처 이미지 픽셀 크기를 기록한다. 에디터 화면 캡처와 게임이 직접 저장한 캡처를 비교한다.
3. 작은 한글·숫자·제목을 제목체와 본문체로 나란히 비교한다.
4. 실기기에서 동일 문구를 확인한다. 화면 레이아웃 개선과 선명도 개선의 효과를 따로 판정한다.
5. UI 재구축 시 Canvas와 TextMeshPro 도입을 검토한다. 현재 Packages/manifest.json에는 uGUI/TMP 의존성이 없으므로 단순 폰트 옵션 변경으로 끝나는 작업이 아니다. 도입 자체를 선명도 해결의 보증으로 삼지 않는다.

프로젝트의 기본 창 크기 540×960만으로 Android 출력 해상도가 540p라고 결론 내리지 않는다.

## 2. 홈 화면

### P1 — 제목이 플레이 화면을 밀어냄

상단 불투명 영역이 350/960, 약 36%를 차지한다. 큰 세 줄 제목은 첫 소개에는 쓸 수 있지만, 반복 방문하는 홈에서는 재화·성장·출발보다 비중이 크다. 오른쪽 빈 공간도 많다.

- 첫 진입 소개와 반복 방문 홈의 역할을 구분한다.
- 홈 제목은 한두 줄의 작은 로고로 축소한다.
- 재화는 상단 한 줄, 중앙은 아빠와 장비, 하단은 다음 목표와 출발로 구성한다.

### P1 — 방치 보상 버튼이 얼굴을 가림

아빠는 바닥 y=700, 표시 높이 330으로 배치되고 보상 버튼은 x=318, y=362, 198×74다. 사용자 이미지에서도 얼굴과 겹친다. 핵심 캐릭터의 표정과 보상 기능을 동시에 훼손한다.

- 보상은 얼굴 밖의 고정 영역에 둔다.
- 작은 상자 아이콘 + `받기`를 중심으로 만들고, 수량은 별도 한 줄로 표시한다.
- 어두운 글자와 녹색 배경 조합은 실제 크기로 다시 확인한다.

### P1 — 출발 전 행동을 설명문으로 전달함

`1-8 1층 복도 · 권장 149 (부족!)`, `아빠 장비 · 강화 · 고무 슬리퍼`처럼 목표·위험·기능·장비명을 한 문장에 묶는다. 전투력 부족을 알려도 곧바로 무엇을 강화할지 연결되지 않는다.

- 다음 목표 카드: 스테이지와 장소, 내 전투력/권장 전투력, 필요한 경우 강화 연결.
- 주 행동은 큰 `출발` 하나. 강화와 도시락은 아이콘과 짧은 이름으로 구분한다.
- 보유 재화, 획득 가능 보상, 현재 장비 상태를 서로 다른 시각 요소로 표시한다.

### P2 — 동일한 판넬이 모든 기능을 지배함

모든 버튼이 3 단위 검은 테두리와 5 단위 아래 그림자를 사용한다. 제목·알림·보조 행동까지 무게가 비슷하다.

- 노란색은 주 행동, 종이색은 정보, 녹색은 긍정 상태처럼 역할을 정한다.
- 굵은 외곽선은 주 행동과 핵심 카드에 집중한다.
- 학교 게시판·학생증·도시락 스티커 같은 소재를 제한적으로 활용한다. 장식보다 여백과 정렬을 먼저 고친다.

| 결과 | 통계·코인·도시락 열기·이유·다음 목표가 긴 세로 판넬에 모인다. | 승패와 핵심 보상을 먼저, 통계는 작게. 다음 도전 또는 필요한 강화 행동이 명확히 이어지게 한다. |
| 도시락 개봉 | 개봉과 장비 비교는 구현되어 있다. 그러나 현재 장비 이름/등급/전투력을 한 줄 18로 표시하고 보조 설명은 16이다. | 현재/신규 비교와 전투력 증감을 분리하고 긴 이름·큰 수치에서도 줄바꿈을 검증한다. |
| 아이콘·카드 | v5/v6는 Bilinear 및 CompressedHQ 임포트 규칙을 사용한다. 폰트와 별개 경로다. | 작은 아이콘의 실제 표시 크기에서 압축 전후를 비교한다. 무조건 Point 필터로 바꾸지 않는다. |

## 4. 리디자인 기준

병맛 캐릭터와 선명한 모바일 UI를 함께 유지한다. 캐릭터를 미화하거나 화면 전체를 화려한 광원·그라데이션으로 덮지 않는다.

권장 홈 구조:

- 상단: 작은 로고 + 재화.
- 중앙: 얼굴이 가려지지 않는 아빠, 현재 장비/성장 변화.
- 중앙 가장자리 또는 별도 보상 줄: 도시락과 방치 보상.
- 하단: 다음 스테이지 정보 → 큰 출발 버튼 → 강화/장비 진입.

공통 문자 규칙의 초기값(540×960 논리 좌표, 실기기 검증 전 가안): 제목 32–40, 버튼 26–30, 주요 수치 24–28, 본문 22–24, 보조 18–20. 공간이 부족하면 먼저 문장을 줄이며, 제목체를 작은 본문으로 사용하지 않는다.

새로 필요한 에셋은 UI 구조가 정해진 뒤 판단한다. 기존 캐릭터·재화·장비·도시락 이미지는 재활용한다. 필요 후보는 작은 홈 로고, 크기 조절 가능한 카드/버튼 바탕, 통일된 탐색 아이콘이다. 글자·수치·상태는 런타임 텍스트로 유지한다.

## 5. 적용 순서와 완료 기준

1. **P1 문자 기준 검증:** 원본 캡처/표시 배율/실기기 비교로 뭉개짐 범위를 확인. 제목·본문 스타일 분리.
2. **P1 홈 재배치:** 제목 축소, 얼굴 가림 제거, 재화/보상/출발 계층 정리.
3. **P2 공통 컴포넌트:** 버튼·카드·정보 행·모달을 통일하고 장비/선택/결과에 적용.
4. **P2 화면 대응:** 9:16과 긴 화면, 노치/안전 영역, 재화 자릿수 증가, 긴 장비명, 잠금/비활성 상태 확인.

완료 판정: 보상 유무에 관계없이 얼굴이 가려지지 않고, 재화와 다음 행동을 바로 찾을 수 있으며, 작은 한글이 실제 기기에서 읽히고, 긴 문구가 버튼 밖으로 넘치지 않는다. 첫 화면을 본 사람에게 다음 행동을 짚게 하는 간단한 사용성 확인도 수행한다.
